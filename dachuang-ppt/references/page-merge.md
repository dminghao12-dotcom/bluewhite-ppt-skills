# 页数压缩与合并页型

先列用户指定的合并映射，再合并重复信息并保留论证。页数由内容范围与答辩时长决定，不把 16–18 页或四页实验方案当下限。以下页型是候选，不是强制模板；坐标只作参考，正文优先保持 16pt，放不下先压缩重复文字。

## 一、先判断哪几页该合并

- 两页讲的是**同一条链**，只是分了两截（技术路线 / 进度安排；配方筛选 / 界面性能）→ 合并成「主体 + 时间轴」或「三步 + 图」。
- 两页是**同层次的问答**（现有不足 / 拟解决问题；问题 / 验证方式）→ 合并成一张对应表。
- 合并后必须仍然回答原来的问题：合并是去掉重复，不是去掉论证。

## 二、五种历史合并页型（结构参考，不照搬旧字号）

以下坐标与字号来自早期稿件，只用于理解结构。新稿正文优先采用当前规则的 18pt，按实际内容重分配空间；不因旧参数写着 11–14pt 就主动缩小正文，也不强制使用其中任何页型。

### 1. 不足 + 关键问题 → 三列对应

一行一主题，三列：**研究不足 / 拟解决的关键问题 / 对应的验证方式**，中间加箭头。

| 元素 | 参数 |
|---|---|
| 列头 | y1.54，13.5pt 蓝粗，居中；x 1.02 / 4.18 / 8.58，宽 2.60 / 3.90 / 3.90 |
| 行 | 从 y1.96 起，行距 1.10；偶数行垫浅底圆角块（h1.02）做斑马条 |
| 序号 | `badge(0.52, y+0.26, 0.44)` |
| 不足 | 标题 16pt 蓝粗 + 说明 13pt（说明压到 2 行以内，超了就到下一行外面） |
| 箭头 | `arrow_right(3.66, y+0.34, 0.34, 0.22)`、`(8.16, y+0.34, 0.30, 0.22)` |
| 问题 / 验证 | 15pt / 13.5pt，框高 0.90，`anchor=MIDDLE`，打 `la` 跳过居中 |
| 底部 | 「项目切入点」通栏框 y5.36 h0.96，左侧标签 15pt 蓝粗 + 右侧一段 15pt |

要点：三列文字都必须**左对齐同一条基准线**；说明文字宁短勿长，否则会顶出色块。

### 2. 技术路线 + 进度 → 上方流程 + 下方时间轴

- 流程条：5 段，每段宽 2.32、间隔 0.20，从 x0.42 起；深蓝圆顶头（h0.52，14.5pt 白字）+ 浅底说明块（h0.66，11pt），段间小箭头。
- 时间轴：左列 2.78 放「阶段一 + 名称」，右列按月份平分（`mw = (12.9 - track_x) / 12`），画 12 条浅灰竖线做月份网格。
- 行：从轴下 0.12 起，行高 0.52、行距 0.72；进度条 `x = track_x + (m0-1)*mw + 0.03`、`w = (m1-m0+1)*mw - 0.06`；每行下方 10.5pt 灰字写「输出：…」。
- 月份刻度与「阶段与时间（月）」标签放在轴上方 0.30 处——**别和上面的说明块抢位置**（抢了就把 `axis_y` 往下推到 3.3 之后）。

### 3. 配方筛选 + 界面性能 → 三步卡 + 三张资料图

- 三步卡：4.05×1.52，x 0.42 / 4.62 / 8.82；圈号 ① 16pt 蓝 + 标题 15.5pt 蓝粗 + 4 条要点 11.5pt（`marker='·'`）。
- 下方三张图 4.05×2.22、图注 10pt 居中；图选「相态曲线、界面张力—盐度、试管相态」这类能直接对应三步的资料图。

### 4. 岩心驱替 → 整幅装置图 + 流程一行 + 四项卡 + 判读

模板里的驱替页常带三维箭头、指标立体块、和内容打架的组织图 → 整页重画。定稿版（17 页稿的 5.3）：

| 元素 | 参数 |
|---|---|
| 装置与流向示意（网页端 GPT 生图，真实色） | `picture(0.42, 1.50, 12.50, 2.56, mode='fit')`，源图比例约 4.3:1；图内自带中文标签（注入泵/中间容器/岩心夹持器/恒温/压力/产出液计量），图下 9.5pt 居中图注带「（示意）」 |
| 驱替流程一行 | y4.44 起，按可读性调整：`饱和水 → 饱和油 → 水驱 → 化学段塞 → 后续水驱`；含水终点、段塞体积与平行样数量必须查申报书，不能把示例稿数值当通用参数 |
| 四项同步记录 | 4 张浅底卡 3.00×0.74，x = 0.42 + i×3.16，y4.90；卡内标题 13pt 蓝粗 + 说明 11.5pt；采收率 / 含水率 / 驱替压差 / 注入体积 |
| 判读口径 | y5.76 单行：红字「判读口径：」+ 12pt 正文（对照、平行样、压差≠调剖） |
| 结论条 | 可选；若与判读或优选说明重复则不放，不为填模板补结论 |

为什么这样排：**装置图回答“怎么做”、流程一行回答“顺序”、四张卡回答“记什么”、判读回答“怎么判”**，一页四件事不重复；比塞两张坐标轴看不清的曲线图更有说服力。曲线挪到数据页用表说话。

生图 brief 要写清：净图位约 5.3×2.0 in、横向、六个中文短标签、深蓝箭头表示流向、颜色接近真实（不锈钢/玻璃透明/原油琥珀/岩心浅灰褐）、不要整张泡蓝、不要夸张 3D、不要数值。

### 5. 创新点 → 4 卡 2×2 + 一条通栏

申请书列五项时不要只放四项：前四项 2×2（6.16×1.62，编号块 0.86 宽），第五项（通常是探索性内容）单独一条通栏 12.5×1.16，标题里标「（探索性）」。卡内标题 16.5pt 蓝粗、正文 14pt。

## 三、在用户那份 pptx 上做合并（不整份重建）

```python
prs = Presentation('用户版.pptx')
kept_notes = {i: s.notes_slide.notes_text_frame.text for i, s in enumerate(prs.slides)}
new = [merge.p32(prs), merge.p41(prs), ...]      # 新页画在末尾
n0 = len(prs.slides) - len(new)
drop_slides(prs, DROP)                         # sldIdLst + drop_rel
reorder(prs, order)                            # 旧页与新页交错排好
renumber(slide, '5.5', '5.4')                  # 页眉编号跟着改
write_notes(prs, old_map, kept_notes, NEW_NOTES)
renumber_partnames(prs)                        # 见 template-reuse.md 坑 1
prs.save('...-17页.pptx')
```

**四个必踩的坑**

1. **备注映射要用「原稿页号」**：删页后剩下的旧页不是连续的 7、8、9，而是它们原来的位置（如 14 数据、16 资源、17 成果、18 经费、19 结束）。按删除后的连续编号去取，讲稿会整体错位，第 13–17 页讲的还是已删页的内容。
2. **备注首行要重写**成「第 N 页 · 页标题」，否则导出的 docx 里还带着旧页码（「第 15 页」出现在第 13 页）。标题取页眉里那个 26pt 文本框；封面/目录/结束页没有页眉标题时给兜底值。
3. **删除后再按索引取形状必错位**：新页绘制与旧页填字分两步做，不要交叉。
4. **页数或图文逻辑一变，讲稿必须同步复核**：`notes_docx.py --rate 250` 只能辅助导出，不能代替对最终页面重新组织语言。按用户时限估算语速与停顿；新页新写备注，被删页内容不残留。最终讲稿流程见 §六。

## 四、合并后必查的三处一致性

- **页眉编号**：按实际保留页连续编号，不把原来的四页实验方案视为固定结构；例如两页实验方案可编号为 5.1 配方与性能、5.2 驱替与优选。目录若合章、改名或删项也要同步。
- **条目数**：与当前项目申报书逐项对齐；例如样板项目为研究内容 5 小节、创新点 5 项、关键问题 3 条，这些数量不作为其他项目的默认值。合并后核对必要条目未遗漏。
- **孤儿图**：合并后原页上的示意图若已无处安放，就撤掉，不要硬塞到新页里凑版面。

## 五、定向压缩：操作顺序与保留校验

1. **读取当前成稿并建立映射**：提取页标题、文字、图片位置、表格与备注；在原页上增量修改，不从旧版生成器重建。用户只要求合并时，不引入额外风格改造。
2. **按语义拆分再合并**：
   - 背景＋意义：先明确图片归属。多图都支撑背景时，用上方较大的背景区逐列对应图、短标题与说明，下方较小区域概括研究意义；不把背景图悬在背景/意义两个分区之外。具体蓝白组件与可调参数见 `style-rules.md`。
   - 现状吸收不足：保留国内外研究依据，用三个短块归纳不足；不拿矿场案例替换原来的文献脉络。
   - 创新吸收问题：五项创新用标题加一句说明，旁列关键问题；不再重复列全套验证实验，探索性项不升级为成果承诺。
   - 实验方案四页压两页：第一页承载配方与相态、界面与适应性及简明进度；第二页承载完整驱替装置、连续实验流程、同步记录指标、数据整合与综合优选。技术路线可由步骤链表达，不必继续独占一页。
   - 成果＋预算：上方精简成果，下方沿用原预算表与示例总额。保持科目、金额、比例及用途口径，不借合并重新分配预算。
3. **安全保留图片与预算**：同页移动图片时先保存对象或 XML，再删除周边形状；同页重插图片 XML 可沿用原关系，跨页复制则必须重建图片关系。编辑预算前保存二维单元格文本数组，保存后逐格比较，不能只核对总额。
4. **同步辅助信息**：成果与预算并章时同步合并目录项；实验方案重新编号；逐页重写受影响备注，使用正式学术语体。页数由映射计算，不把某个案例的 12 页固定为所有开题的标准。
5. **验证未涉及页确实未改**：修改前保存未涉及页的 `sha256(slide._element.xml.encode()).hexdigest()`；输出后用原页到新页的映射重读并比较哈希，避免全局整理脚本悄悄改动封面或字号。另核对输入文件哈希未变、预算单元格一致、PPTX ZIP 无重复路径。
6. **实际渲染再交付**：导出 PDF，逐页检查合并页和目录，不只看总览；核对图注、字号、遮挡、目录残行与页数。保留原稿，另存有区分度的合并版；交付简述合并项、原样保留项及核验结果。

这些是内容组织方案，不是按索引可套所有稿件的通用脚本；先读取当前对象结构，再应用。

## 六、最终版 PPT 的配套讲稿

1. **先读最终文件，不只读备注**：逐页提取标题、正文、表格、图注和备注。以当前页面为准核对页数与顺序，剔除备注中的旧页号、已删内容、过时分工或未经证实的参数；图片归属或上下/左右顺序改变时，讲解顺序也随之调整。
2. **另写逐页正文，再导出**：每页一个标题和一至数段可直接试讲的文字，采用正式科研申报语体。创新词对应具体方法，优异性能表述为拟实现的筛选目标；明确文献/矿场案例不是本项目结果，示意图不等于实物装置，示例经费不等于批复。未知成员姓名、人数和未落实条件不编入朗读稿。
3. **将朗读稿与使用提醒分开**：正文保持叙述完整，不混入“这张图沿用原稿”等制作说明。待确认人员、示例预算及材料性质集中放在文末“上台前确认（不朗读）”。
4. **用工具计算用时，不凭感觉命名**：统计实际朗读正文，排除标题、页码和使用提醒；可用每分钟 240–250 个汉字作初始估计，再加翻页及图示停顿，逐页标注建议秒数。英文术语和数字的读法会影响速度，所有结果写明是估计，最终以试讲校准，不承诺精确时长。
5. **同源生成 Word 与 Markdown**：先保存含页号、标题、段落的单一结构化文本，再导出两种文件，避免分别修改造成内容分叉。文件名对应实际 PPT 页数，不沿用旧稿的“10分钟”标签。仅用户要求讲稿时，读取但不改 PPT；以文件哈希核对未被修改。
6. **核对内容和实际版面**：重新读取 DOCX，确认每一页 PPT 都有一节且正文完整；实际转为 PDF 查看首尾及长段落页，检查字体、标题、裁切和空白页。需要按章节分页时，在目标标题设置 `page_break_before`，不要依赖可能被挤到下一页的独立分页空段落；转 PDF 后逐页检查非空。
7. **保留可维护的最新交付**：正文源文件与工程保留，向用户提供最新 `.docx` 与 `.md`；中间渲染与版本备份留工程目录，不作为一堆重复交付。讲稿通过核验不意味着旧 PPT 备注已同步，未写回时不要声称已同步备注。
