# 装置 / 设备示意图：先交网页端，矢量只是备选

## 谁画

| 图是什么 | 谁画 |
|---|---|
| 结构、流程、机理、场景、概念插画 | 网页端 ChatGPT 生图 |
| **具名实验设备的装置图（哪怕用户给了实拍照片）** | **网页端 ChatGPT 生图，照片作为参考图一起上传** |
| 用户明确说「你自己画 / 别叫 GPT」 | 原生形状（见下面「备选：原生形状画法」） |

把照片传给生图端，需求里说明「这两张是实验室实际在用的设备；上一版把注入泵、中间容器画成了透明玻璃瓶」——
它一轮就能给 2172×724 的写实装置长图，中文设备标签（高压注入泵 / 中间容器 / 岩心夹持器（恒温）/ 压力表 / 产出液计量）全对。
同一图位它会给多版（悬浮白底版 vs 全不锈钢带底座版），**两版都取回、拼一起看，让用户挑**，不要拿第一版就定稿。

按照片在本机用矢量重画也能对上设备形态，但用户看过成图后直接判「很丑，不是我想要的效果」——设备图不要走自绘。
照片是参考、不是素材：背景杂的快照不直接贴页面（除非用户要照片版）。

## 比例不匹配：放大 + 下移，不裁不拉

生图端常给 3:1，图位常是 4.3:1（如 10.99×2.56 in）。做法：

1. 定新的图高（例：2.56 → 3.00 in），宽度 `w = h * w0 / h0`，超过图位宽就反过来按宽度卡；
2. 图顶对齐原图位顶部（例 y=1.42），**水平居中**；
3. 把该页图注、流程行、指标卡、两栏文字按名字整体下移（例 +0.22–0.32 in），逐个 `shape.top = Inches(...)`；
4. 下移后重算最底元素与页底结论条/优选原则条的间距，压到一起就再压 0.04–0.06 in。

裁上下会切掉设备顶部管路与底部标签，压扁会让不锈钢件失真；放大 + 下移是唯一不损伤图的解法。

## 备选：原生形状画法（仅用户明确要矢量时）

### 岩心驱替装置画法（13.33×7.5 页，图形区 y≈1.58–3.55）
一条水平主线串四台设备，每台下方一个 11.5pt 蓝字标签，图注在 y≈4.14。

**注入泵**：机身圆角矩形（浅灰渐变）+ 深色面板（屏幕块、3×4 键盘点阵、黄色功能键条、红色电源块）
+ **左侧两个水平柱塞泵筒**（圆角矩形 `radius≈0.35` 成胶囊状）+ 泵筒右端小方块接进机身。
泵筒是识别关键——只画一个方盒子，读图的人会认成机箱或电脑。

**中间容器**：立式圆筒（宽 0.62–0.70、高 1.00–1.10 in）+ 上下压盖（比筒体宽约 0.2 in）
+ 顶部螺纹接头 + 筒身 3–4 条横线做螺纹纹路 + 左右侧向进出短管（高 0.09 in，**同一高度**，便于画直管线）。
不画液位、不画透明。

**岩心夹持器**：金属筒（`radius≈0.18`）+ 两端法兰（窄矩形）+ 内部岩心（暖黄）+ 外套浅蓝恒温框 + 上方「恒温」标注。

**压力表**：钢圈 + 白盘 + 红指针 + 向下短接管接到主线上——表**骑在管线上**，不要悬在空白处。

**产出液计量**：两个量筒（浅色筒身 + 底部油/水色液位）+ 刻度线 + 托盘。

**管线**：`sline` + 三角箭头，箭头停在下一台设备的边缘。箭头插进量筒筒体是常见失误，改坐标到筒左沿。

**不锈钢质感** = 两档水平渐变（`#9FA9B8` → `#E6EBF2`）+ `#7C8798` 细边。

## 项目 `deck/lib.py` 的四个坑（和技能 `scripts/lib.py` 不是一份）

1. **`gradient(s, c1, c2, c3=…)` 传三档必崩**：`IndexError: list index out of range`（`pptx/dml/fill.py __getitem__`）。
   `s.fill.gradient()` 只生成两个 stop，库里「`len(stops)<3` 就再调一次」并不增加档数。用两档渐变即可。
2. **`judgment()` 不解析 `【】`**：它把整句写成红色粗体（本项目风格），`rich()` 那套方括号标红只存在于
   技能版 `scripts/lib.py`。项目里写 `【词】`，括号会原样落进 PDF，交付前 `verify_deck` 报
   「PDF 里残留 N 个方括号标记」。判断句写纯文本。
3. **项目 lib 没有 `header()`**。页眉手写，坐标照抄已有页：
   编号框 `(0.41, 0.15, 0.92, 0.45)` 26pt `#003195` 加粗；标题 `(1.34, 0.15, 9.6, 0.45)` 26pt；
   右上 logo `add_picture(height=Inches(0.72))` 后 `pic.left = Inches(12.92) - pic.width`；
   0.80 in 处通栏细线 1.25 pt。
4. **`bullets()` 的纯字符串条目不解析 `【】`**：只有 `judgment` / `conclusion` 内部走 `rich()`；
   正文里直接写 `'交付【标准化数据集】，…'` 会被原样打印，`verify_deck` 报「PDF 里残留 N 个方括号标记」。
   每条用 `lib.rich('…【词】…')` 包一层再传给 `bullets`（它返回 `[(text,color,bold)]`，正好是多段富文本格式）。
   改完还要重数每页红字：一页超 4 处同样过不了核验。

## 插页与页序

```python
s = prs.slides.add_slide(prs.slide_layouts[6])   # 先在末尾建
# …画内容，写 notes…
lst = prs.slides._sldIdLst
ent = list(lst)[-1]; lst.remove(ent); list(lst)[target_idx].addprevious(ent)
```

`addprevious` 只动这一页；「全删再按新序 append」容易把其它页的相对关系弄乱。
页眉编号是硬编码文字，插页后要同步后续页编号与目录页条目。

## 页数一变，讲稿要重生成，不要手改

讲稿脚本常把页数写死：`assert … == 12`、输出基名 `…-12页配套`、`ppt_pages_matched: 12`、
intro 里「对应最新 12 页」。做法：

1. `cp deck/speech_current.json deck/speech_13p.json`，插入新页条目，后续条目 `page + 1`；
2. `cp deck/make_current_speech.py deck/make_speech_13p.py`，改 JSON 路径、PPT 文件名、断言、输出基名、intro 文案；
3. 跑出新 docx + md，**旧页数版本原样保留**，不覆盖用户手上那份。

新页条目按同页其它条目的语体写（正式、名词化），字数按「170–190 字/页」。
