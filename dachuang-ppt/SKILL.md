# 大创 / 申报答辩 PPT

## 〇、运行约定与开箱须知（先读）

- `$S` = 本技能目录，`$PY` = 装好依赖的 Python（见 `INSTALL.md`：`python-pptx python-docx lxml Pillow pymupdf`，渲染要 LibreOffice）。
- **起手用 `deck-starter/`**：7 页骨架，`$PY -m deck.build2` 直接出 pptx。拷到项目目录后找不到默认模板时，设 `DACHUANG_SKILL_DIR=$S` 或手放 `tpl2/t.pptx`。改造顺序：换模板 → 改 `COVER` 形状名 → 改 `TOC` → 写 `pages1/pages2` → 同步讲稿条数。见 `deck-starter/README.md`。
- **`scripts/` 是通用组件**：`lib.py`（组件库，字号阶梯 `FS`、➤ 分点、悬挂缩进已按本文件规则内置）、`merge.py`（合并页型的参考实现，**文字是原项目的，只抄版式**）、`tidy.py`、`rich_text.py`、`verify_deck.py`、`script_timing.py`、`apply_notes.py`、`make_default.py`、`bg.py`、`prep_images.py`。
- **`examples/project-reference/` 是作者原项目的入口与填模板代码**（`build2.py` / `tpluse.py` / `shrink.py`，写死“中相微乳液”等文字，依赖未发布的 `pages1/pages2/notes2`），**只作写法参考，不能直接运行**；换项目用 `deck-starter/deck/tplcore.py` 的 `by_name + set_text` 按形状名改。
- `verify_deck.py` 的 `--pdf` 可选。Windows 上 PowerPoint COM 导出报 `0x80004005` 时手动另存 PDF 再传 `--pdf`。
- **提问**：有提问/澄清工具就用，没有就直接文字问。**生图**：用户指定网页端 ChatGPT；agent 不能操作浏览器时把需求写成提示词交给用户，先留图位排版。**交付**：用所在 agent 的发送文件方式把文件直接给用户。
- 文中提到的 `chatgpt-web-planning`、`business-ppt` 等是可选配套技能，未安装时按本文件的手工做法完成。

## When to Use

- 用户要做**大学生创新创业训练计划（大创）**、**挑战杯 / 互联网+ / 学科竞赛（节能减排、电子设计、数学建模等）**、校级省级项目或基金项目的**申报答辩、路演、结题汇报**PPT。
- 特征：短时评审现场，有申报书/商业计划书作为内容源，并有参考模板或现有成稿；按用户指定范围与时长确定页数，不以某个案例的 12 页或 17 页为固定标准。
- **不适用**：组会/文献汇报/学术答辩（那走 `research-ppt-skill`，同样正文 18pt，页数按时长）。

申报答辩与学术报告不是一回事：页数少、每页信息密度高、必须套用户那份模板、口径以申报书为唯一事实来源。

本技能的规则来自作者跑通的一份样板工程（中相微乳液驱油体系，20 页）；工程本身未随包发布，`examples/project-reference/` 与 `scripts/merge.py` 里的文字都出自它。

## 一、开工前要拿到的东西

1. **申报书**（docx/pdf）——内容唯一来源，不得编数据、阈值、结论。
2. **模板 PPTX**——用户手挑的那份；风格以它为准，不要另起炉灶。
3. **资料 PPT / 原始图**——只取图，数字不搬（示例体系的数据不能写成项目结论）。
4. **评审场景信息**：时长（常 10 分钟）、页数上限（常 ≤20）、汇报人、指导教师、单位。
5. 缺的信息留占位并注明：成员姓名用 `＿＿＿（分工）`、经费标「示例」。
6. **用户拿一份新素材说「重新来」时，先一次性问清两件事（有提问／澄清工具就用它）**：这一版是答辩稿还是文献汇报、页数与章节是否沿用上一版。口径不同等于整份重做（15 页白做一轮），宁可多问一句。
7. **用户说「按最新的 skill 做」时，先找新包，再定用哪套版式**：章节串（「背景及现状 2 + 目的 2 + 方法 2 + 历程 2 + 关键技术 3 + 创新 2 + 意义 2」）只说明这是哪类稿，**不说明用哪个技能**。先看用户最近发来的附件、下载目录和 agent 的技能目录里有没有刚发来的 zip / 解压目录 / 新增的 `SKILL.md`；有就按那份做（例如 JS 版 `business-ppt`，若已安装，同一串章节的版式映射见它的 `references/research-defense.md`），章节串与本技能的 15 页版一模一样也不构成沿用本技能的理由。确认没有任何新包，才用本技能。

## 二、参考页序（按内容与时长合并）

**先按用户指定的合并范围和答辩时长决定页数，不设固定页数下限。**下表是较完整的 17 页参考结构，不是必须保留的目录；短时开题可以进一步合并。先列出「原页 → 目标页 → 保留要点」，再去掉重复阐述，保留研究问题、实验逻辑与必要证据。不要为凑页数、填卡片或套模板增加内容，也不要把多页缩小后硬塞一页。具体合并配方与核验步骤见 `references/page-merge.md`。

| 页 | 内容 | 编号 |
|---|---|---|
| 1 | 封面（模板原件，只换字与校徽） | — |
| 2 | 汇报提纲（八项单列竖排） | — |
| 3 | 小组分工与指导老师 | 1.1 |
| 4 | 研究背景 | 2.1 |
| 5 | 技术定位 | 2.2 |
| 6 | 研究意义 | 2.3 |
| 7 | 国内外研究现状 | 3.1 |
| 8 | 现有不足 + 拟解决的关键问题（合并） | 3.2 |
| 9 | 项目创新点（按申请书逐条列全） | 4.1 |
| 10 | 技术路线 + 进度安排（合并） | 5.1 |
| 11 | 配方筛选 + 界面性能（合并） | 5.2 |
| 12 | 岩心驱替与增油评价 | 5.3 |
| 13 | 数据整定与综合优选 | 5.4 |
| 14 | 项目资源 | 6.1 |
| 15 | 预期成果 | 7.1 |
| 16 | 经费预算 | 8.1 |
| 17 | 结束页 | — |

**结题 / 中期答辩的 15 页版**（用户按章节指定页数时常用）：研究背景及现状 2 + 研究目的 2 + 研究方法 2 + 研究历程 2 + 关键技术与创新性 5（关键技术 3 + 创新 2）+ 研究意义 2，另加封面、目录、结束页 = 18 页。研究历程两页用「左时间轴（4 个节点：时间/小标题/一句结果）+ 右 1–2 张资料图 + 页底尾结论」；时间轴的节点标题框也要打 `la`，否则 ≤28 字的标题会被居中、与下面的描述文字错开。

**大赛路演版目录参考**（同一套版式，按材料取舍）：项目背景与痛点 / 解决方案 / 技术方案与创新 / 竞品与壁垒 / 实施进度与资金 / 团队 / 预期成果 / 财务与风险。目录项与页数随实际内容合并，不强制八项或 16–18 页。

**论文 → 会议汇报的 20 页版**（用户丢一篇论文说「严格按这个技能做，20 页左右」时）：1 封面 2 汇报提纲 3 研究背景 4 研究意义 5 国内外研究现状 6 研究思路与技术路线（AI 架构图横贯整幅）7 数据来源与样本构成 8 方法/智能体构建 9 验证方案设计 10–12 验证结果三页 13 情景／实验设计 14 主效应 15 健康或终局效应 16 分组差异 17 稳健性 18 讨论（偏差 + 贡献双栏）19 结论与政策启示（含一条局限条）20 结束页 = 17 页正文。用户点名「研究背景 / 研究意义 / 研究现状 / 研究思路」时，这四页各自独立，不要合页；「创新点」并进讨论页右栏，比单开一页更省页。

需要 20 页时的拆法（备选，不推荐默认用）：把 3.2 拆回「不足」与「关键问题」两页、5.1 拆回「技术路线」与「进度」两页、5.2 拆回「相态」与「界面」两页。

## 三、核心做法：在模板上增量改，不要空白重建

**先锁定修改范围**：用户给出现有成稿并指定合并时，以该成稿为基准另存工作副本，只改涉及的页及必要的目录、编号、备注。封面、团队、技术定位、资源、结束等未涉及页面保留原对象，不重新生成，不顺带统一格式。PPT 修改不等于授权修改技能；技能更新另需用户明确授权，不顺带改其他 PPT 技能。

模板页能直接用就**直接改它的文字框与图片位**，不要重画。判断标准：

- **能套**：封面、目录、判断句条、双卡+小指标页、指标块页、成果页、结束页。
- **不能套**：它自己的业务版式（如「四课题矩阵」「装备介绍」「团队页带图标组合」）。硬套会排版打架——尤其带图标的组合（group），一改宽高图标就跟着缩放变形。这类页改自绘。

套模板手法与坑见 `references/template-reuse.md`。速记：

1. `Presentation(模板)` → 按 `sldIdLst` 删掉不需要的页（同时 `prs.part.drop_rel(rId)`）。
2. 保留页逐页 `fill_xxx(slide)`：`set_text`（保留首个 run 的字体属性）、`set_pic`（换 `r:embed`，保持位置尺寸）、`drop`。
3. 自绘页用 `prs.slides.add_slide(prs.slide_layouts[6])` 加进来，再按目标顺序重排 `sldIdLst`。
4. **必须**重编 partname（见 references 坑 1），否则 zip 里出现重名 `ppt/slides/slide11.xml`。
5. 新建整稿时可运行 `tidy.apply()`；标红**不要**再跑 `emphasis.apply()` 自动挑词，改用 `scripts/rich_text.py` 的方括号标记（见 `references/style-rules.md`）。增量修改只对受影响页面处理对齐、字号和强调，避免全局脚本改坏用户已调整的页面。合并后对未涉及页比较 slide XML 哈希，并检查原文件未被覆盖；具体方法见 `references/page-merge.md`。

命令：

```bash
cd <项目目录>
$PY -m deck.build2            # 生成 out/*.pptx
soffice --headless --convert-to pdf --outdir out/render out/xxx.pptx
$PY - <<'EOF'
import pymupdf   # 旧版本写作 import fitz
d=pymupdf.open('out/render/xxx.pdf')
for i in range(len(d)): d[i].get_pixmap(dpi=100).save(f'out/render/p{i+1:02d}.png')
EOF
```

然后**逐页看图**（不要只看总览）。

**同一份稿要整份重做（换插图、换语言、按新版规则重排）时，不要从零重写 `pages.py`**：先 `cp pages.py pages_v2.py`，再写一段「带断言的批量替换」脚本改内容与图名——每处 `assert s.count(old) == n` 再替换，命中数不对就报错，既不静默漏改，也避开部分 agent 文件写入工具对未读全文的覆盖拦截。重建走 `python -m deck.pages_v2`，`make_docs.py` 里的 `from deck.notes import NOTES` 要同步改成 `notes_v2`，否则交的是上一版讲稿。

## 四、版面规则（用户已定稿，照做）

完整版见 `references/style-rules.md`（字号/对齐/颜色/封面/目录/结论条/图注逐条规定）。下面的表是速查：

**字号阶梯：12 / 14 / 18 / 19 / 20 / 21 / 26 / 72**（`lib.FS`：图注 / 标签 / 正文 / 分点小标题 / 首结论 / 尾结论 / 页眉 / 封面计划名）
- 页眉：编号（`3.2` 这种「章.节」写法）26pt + 标题 26pt，编号框宽 0.92in，标题左边界 1.34in。
- 首结论（页顶）：白底细边框 + 蓝色三角引导 + 20pt 黑体加粗左对齐，只标核心词红，**不要左右加竖杠**。
- 尾结论（页底）：深蓝渐变通栏 + 白字 21pt 居中，关键短语用亮红 `#FF6060`。
- **正文与卡片正文 18pt**（用户定稿：18 合适，再大嫌大）；图注 12pt 居中；标签 12–14pt；表格正文 16pt。完整规格见 `references/style-rules.md`。
- **正文分点：行首蓝色箭头 `➤`，小标题比正文大一号**（正文 18 → 小标题 19；`bullets(items=[{"label":…, "text":…}])` 自动放大一号）、蓝色加粗、与正文同段排；卡片里的分点条目同样带箭头。少了箭头或标题与正文同号，用户会直接指出来。
- **行距与悬挂缩进（用户原话「分点行距很不舒服」）**：正文行距 **1.44**、卡片内 **1.40**、段后 10pt；分点段落加 **0.30 in 悬挂缩进**（`pPr` 的 `marL=0.30in` + `indent=-0.30in`），换行后的文字与分点正文对齐而不再退回箭头下面。行距低于 1.4 时中文挤成一片、块与块分不清，用户一眼看出来。规格与重算方法见 `references/style-rules.md` 的「行距与段首缩进」。
- **页标题与小标题用学术名词**：页标题按「研究背景 / 研究意义 / 国内外研究现状 / 研究思路与技术路线 / 数据来源与样本构成 / 验证方案设计 / 结论与政策启示」这套口径；分点小标题同样是名词短语（「结局排序能力」「总量估计偏差」「分组偏差」），不写「能区分谁上网、谁体检」这类叙述句。用户会用「大标题和小标题要足够专业」直接提这条。
- 放不下就压条目（三条以内）或拆页，而不是把字号降回 13；实在放不下才留 16，并接受该页小一号。

**结构**
- 页面以页眉（编号+标题+右上校徽）和主体为基础；判断句、卡片与结论条按信息需要选用。逐页判断页底结论是否提供必要收束：能明确研究启示、适用边界或优选原则且空间足够时保留；重复正文、没有实质判断或挤占图文时不放。不要统一添加或统一删除，也不要按固定纵坐标整批删除页底对象——图注、预算说明和封面信息也可能位于那里。
- 丰富排版靠信息主次与结构变化，不靠增加卡片或装饰：按内容交替使用图文不对称、国内外对照、编号条目、实验步骤配图、表格配定量图。现状与不足同页时，先按实际文本高度收紧上方现状框，再给下方不足分配空间；三列不足若导致短标题与长说明错落，改为等宽横向条目，统一编号、标题和说明的列边界。
- 实验方案优先分点，每个模块通常三条，采用「项目标签：具体操作或指标」；标签蓝色加粗、说明黑色常规，条目按实际段落排版，避免一段连续文字或整段同色加粗。
- 对有明确类别标题的内容区，优先复用参考稿的**蓝色渐变标题带＋白色主体＋浅蓝细边框＋圆角**：标题白字居中，正文按语义左对齐。创新点与关键问题可左右双栏分别套此组件；不要用整块浅蓝底或交替色带替代用户指定的蓝白结构。丰富版式不等于弃用已认可的组件。
- **先确定图片归属，再决定分区方向**：背景与意义合页时，若多张图均支撑背景，采用上下结构——上方较大区域为研究背景，按证据主题分成三列等宽的竖向图文单元，每列上图、图下注明来源、下方标题及解释；下方较小区域概括理论、应用、育人意义。不要将背景图片悬在背景/意义左右分区之外，也不要把图误归到意义区。图文必须逐列对应，不为凑三列杜撰证据；空间不足时省略重复的页顶判断句，先保住分区逻辑与正文可读性。参数与复用步骤见 `references/style-rules.md`。
- 卡片内**不要分隔线**，靠序号/留白分层。
- 封面与结束页只放必要文字：封面 = 计划名（72pt）+ 项目名（26–28pt）+ 细线 + 单位与时间；结束页 = 感谢语 + 副句 + 白色细分隔线 + 单位与时间。**不要**在页内重复「XX 计划项目申报答辩」小字。
- **封面/结束页的多段文字要逐段设对齐**：`tplcore.set_text` 只改首段的 `alignment`，模板第 2 段常是左对齐——副标题两行会出现一行居中、一行左偏，整块看成楔形（用户会说「封面怎么改得这么丑」而说不清哪里）。改完遍历 `text_frame.paragraphs` 逐段 `PP_ALIGN.CENTER`；副标题两行**手动断行**且字数接近（15 字 / 15 字这种），靠自动换行必断出长短孤行。
- **结束页一律整块重绘**，不要 `set_text` 改模板原框：模板那两段对齐不一致，字号还会被继承成偏大一档。感谢语 44pt / 副句 30pt / 白色细线，整套落在深蓝背景区内（蓝区约 0–5.0 in），并删掉模板自带的「汇报人／指导教师」胶囊。封面删掉空的「汇报人：＿＿＿」胶囊后下半幅会空，用「细分隔线 + 单位／会议名」居中收口。
- 目录：单列竖排，项数与实际合并后的章节对应；八项参考稿可从行距 0.66、19pt、序号圆 0.58 试排，删掉模板底部装饰图，按内容保留合理底部留白。

**颜色**
- 主色深蓝 `#003195`，浅底 `#F2F5FB`，边框 `#C1CCE4`，正文 `#1A1A1A`。
- **红色只用于两处**：首/尾结论与正文里的核心词。正文标红必须**逐段人工用方括号标记指定**（每段 1–3 处），不要跑 `emphasis.py` 自动挑词——自动版挑到的是泛词和半截词，还漏掉真正的判断句。
- 不做整块实心红条（底部说明条用浅底+细边+蓝字）。不要给示意图编造高饱和配色。

**对齐**
- 「左标题+左正文」的卡片：标题、正文、序号三者左边界必须同一条线；这类框打 `la` 标记跳过全局居中。
- 表格：全部单元格水平+垂直居中。

## 五、配图

1. **优先用资料原图**（相态曲线、界面张力、显微图、井场、装置）；等比缩放，不允许拉变形。
2. **结构/流程/机理/装置示意图一律交网页端 ChatGPT 生图**（装了 `chatgpt-web-planning` 技能就按它走；没装就把需求写成提示词交给用户去网页端生成，图位先留空，不本机自绘），不要用 python-pptx 色块或原生形状拼；也不要用本机生图工具。**具名实验设备也一样**：把用户拍的实物照片作为参考图一起上传，并在需求里点明「上一版把注入泵、中间容器画成了透明玻璃瓶，这两张是实际在用的设备」——它会给出写实渲染的装置长图，中文设备标签通常一次就对。按照片自绘设备图会被判「很丑、不是我想要的效果」，白烧一轮；只有用户明确说「你自己画 / 别叫 GPT」时才走 `references/native-diagrams.md` 的备选矢量画法（那份文件另含 `deck/lib.py` 的三个 API 坑、插页、讲稿重生成）。
3. 生图需求只写四件事：背景用途、这页要立的判断、**净图位尺寸与比例**、图内不要数值；**不写画风**——不写「蓝白信息图风格」「学术风」这类标签，也不预设配色（不要替它说“颜色接近真实”）。画风由它判断，理由与写法见 `chatgpt-web-planning`（若已安装）的「别在需求里贴风格标签」。
4. 收到图后裁白边、转 JPG（宽 ≤1500）、按槽位宽高比放置；图注居中压在图片正下方。
   **生成图比图位更方时**（如 3:1 的装置长图要塞进 4.3:1 的图位）：按图位**高度**等比放大到不越界（宽度上限仍取图位宽），再把该页图注、流程行、指标卡、两栏整体下移到算出来的新位置——不裁设备、不拉伸变形。裁上下会切掉设备的顶部管路和底部标签，压扁会让不锈钢件失真。
5. 每张独立图片保留一条居中的对应图注，标清资料图或示意；多图页可以逐图标注，不限制全页只能有一条。删除同一图片的重复图注，不删除必要的图源说明。
6. **交付前做一遍图源核查**（评审会盯这个）：
   - AI 图只做「示意」，图注必须带「示意」；资料原图带「资料图」或「文献报道」，保留原坐标轴与单位。
   - 图内中文标签逐条比申报书用词（Winsor Ⅲ、超低界面张力、双向增溶、润湿反转、流度调整等），不一致就改图或改字，不能一张图一套说法。
   - AI 图内不得出现数值、性能承诺或「已实现」类表述。
   - 用人名占位的图（成员 A–D）必须在同页配「角色—姓名」对照表，否则让 GPT 重出、直接把名字写进图里。
   - 合并/删页后检查孤儿图：图上标签对应的内容已被删掉的，图也要撤。
7. **从论文 docx 取图**：`unzip -o 论文.docx -d x/` 后取 `x/word/media/image*`。这些图多为 **RGBA 透明底**，直接 `.convert('RGB')` 会变黑底（看着像整张图反色）——先 `Image.alpha_composite(白底, im.convert('RGBA'))` 再裁边。
8. 资料原图若用了与全稿冲突的配色（如绿色线框的技术路线图），用 HSV 把绿相旋到蓝相（保留明度/彩度）即可，不必重画，并保留图注「资料图」。
9. **论文是 PDF 时直接从 PDF 取原图**，比截图清晰得多：`for p in doc: for img in p.get_images(full=True): pymupdf.Pixmap(doc, img[0]).save(fn)`；`pix.n > 4` 时先转 `pymupdf.Pixmap(pymupdf.csRGB, pix)` 再存。排版/翻译稿里的图仍是原始位图（1400–2000 px），够 5–6 in 的图位用。
10. **一张大图里有多排子图时，按内容切开再用**：常见的「a–i 形貌 + j 反应式 + k 示意」整张图塞不进一页，按行白度剖面找切缝 —— `rows = (arr > 248).mean(1)`，取 `rows > 0.95` 的连续行区间，选最宽的一条当切缝，两块分别配图注。切完**必须逐块打开看**：切在反应式中间会把上半段（如偶联那一步）整块切丢，本机连切两次才发现；合格标准是两块各自能独立成群、上下不残、文字不全被切。

11. **先定图位级别，再发生图需求**：大图（5.6×3.4 in 起，页面主视觉）／中图（5.4×3.2 in，一个主关系）／小图（净高 1.0–1.4 in，卡片内配图）。级别在排版前就定好，按级别给尺寸与文字密度：**小图一律要求图内零文字、只画关系**，中图少量短标签，大图才允许铺陈。
12. **卡片塞不下图时先删旁枝，别缩字号**：步骤卡/问题卡里「控制点」「工艺窗口」这类解释性旁枝删掉，改成「顶部小图 + 2–3 条主参数」；小图净位约 3.67×1.40 in（3 列）或 2.63×1.12 in（4 列），图下补 9pt「示意」。

13. **宽架构图（≥2.5:1）的标签会叠印**：让网页端画「研究思路／总体架构」这类横贯整幅的长图时，需求里限定「每组最多四行、每个标签只印一次、标签四到六字」，并要求它出图前自查；重出两次后仍有个别字叠印或错字，就按行做背景插值再本机重画该标签（比第三次重出快，也不动其余部分），重画后放大逐字核一遍。**论文自带的 16:9 设计图塞进 9 in 宽图位时正文只有 6–7pt，投影不可读**——这种位置直接换成 AI 架构图（12.3 × 3.55 in 横贯整幅），细节留给右栏或下一页，不要为保住「资料图」硬塞。

已跑通的七个位置：三相结构（2.2）、分工结构（1.1）、关键问题链（4.2）、技术路线（5.1）、实验条件顺序（6.1）、四重作用机理（2.3/7.1）、相态判读四步（5.2）。

## 六、内容红线

**先定研究语体，再排版**：页面与讲稿采用正式科研申报表达，用「构建、揭示、阐明、优选、验证」明确研究动作；将「必须回到岩心」「同步给出」「先……再……」等口播式指令改为研究方法、评价指标或学术判断。关键问题可用「明确……规律」「阐明……影响」「建立……评价依据」表达，不必全部写成问句。

**逐句扫口播与比喻式表达**（用户会直接要求「语言学术一点、官方一点、站在他们的角度」；写成小标题再改一遍）：

- 比喻收尾的判断句 → 名词化判断：「卡的正是非共价作用」→「受制于纤维间非共价相互作用」；「是……的必答题」→「是……的前提」。
- 口语动词短语 → 书面动词：「把强度做上去」→「提升强度」；「接在同一个分子上」→「引入同一分子骨架」；「走得进去」→「可作为传输介质」；「拆得开」→「按需解键」；「靠试」→「依机理开展」；「二选一」→「不再互斥」。
- 设问与自问自答（「分子有没有接上？」「成没成键？」）→ 陈述判断（「该阶段解决分子结构构建与晶型保持」「谱学表征确认化学键合」）。
- 夸张量词 → 量化表述：「翻近五倍」→「提高至约五倍」；「骤降」→「显著下降」；「一下子」删掉。
- 讲稿同标准：不是把页面文字念一遍，但也不能带口播腔；写完逐句念一遍，凡是要加语气词才顺的句子都要改。

**适度突出创新与优势，不把去 AI 味等同于删掉评价性表达**：在与申报书创新内容对应的方法处可用「创新性地」，在预期目标处可用「筛选性能优异的候选配方」等具体表达。评价词必须说明优在何种性质；避免空泛堆砌「优秀、先进、领先」，不得把拟开展的创新、预期优异性能写成已证实成果，也不自行增加「首次、国际领先」等优先权或比较性断言。

- 只写申报书里有的东西；推导性结论标「待实验验证」。
- 不编阈值（如「重复性 ≤5%」），改成方法性表述（「以重复性核查为准」）。
- **摘要与正文的数字口径冲突时以正文为准**（例如摘要写「抗折提升 12 倍」、正文写「耐折 13 折 / 纯纸 8 折」），全稿统一一种说法，不把倍数与绝对值混用；两处口径不同时在交付说明里写一句依据。
- 论文没给时间线时，研究历程用「阶段一…阶段八」这类阶段名，不编年月；用户给立项/中期节点再换真实月份。
- 引用文献/现场数据带来源标签（「资料图」「文献报道」）。
- 经费比例若未定，标「示例」。

## 七、交付

放在用户指定的交付目录（未指定时 `<工作目录>/交付/<项目名>/`），再用所在 agent 的发送文件方式把文件直接给用户：

```
<项目>-申报答辩-<N>页.pptx
<项目>-申报答辩-<N>页.pdf
讲稿-<项目>申报答辩-<N>页配套.docx
讲稿-<项目>申报答辩-<N>页配套.md
```

**讲稿以最后交付的 PPT 为准，不直接照搬旧备注。**按最终页序、标题及图文顺序组织正式答辩表达，标注逐页建议用时；外部案例、示意图、示例预算和待定信息保持各自性质，不编补未知成员。默认提供便于转发的 Word 与便于修改的 Markdown。详细流程、时长计算与文档核验见 `references/page-merge.md` §六。

验收：跑 `scripts/verify_deck.py --pptx … --pdf … --docx …`（判据：页数一致、16:9、每页备注非空、PDF 无 `【】` 残留、每页正文红字 ≤4，尾条 `#FF6060` 不计入），输出「全部通过」才算过检；讲稿各节与最终幻灯片逐页匹配；按实际正文字数和语速估计时长，并预留翻页停顿，以用户时限和试讲结果为准，不默认所有稿件均为 10–12 分钟。用户仅要讲稿时，不改动 PPT 或技能。

讲稿篇幅按页给：一页 **170–190 字**，15 页正文合计约 2 800 字，按 4.3 字/秒 ≈ 11 分钟。第一版常写成 250–300 字/页（≈17 分钟），交付前先按字数核一遍再压。
**改成书面语后会变长**：同一套内容从口语改学术体，实测 2 805 → 3 327 字（≈11 分 → 13 分）；重写语体后必须重新算时长，并告诉用户可以删哪几页来压时间（通常删 1.2 现状、3.2 表征、创新两页各一句，主线不受影响）。

**时长不手算**：`$PY scripts/script_timing.py 讲稿.md` 按页统计正文字数、重写每页「建议用时」并重建汇总表（4.3 字/秒），同时打印总字数与分钟数——改完语体或加页后重跑一次，别用上一版的数字报给用户。

**讲稿只维护一个来源**：把讲稿写成 md，`scripts/apply_notes.py 稿.pptx 讲稿.md`（build2 末尾也可 `from deck.apply_notes import parse` 直接调用）逐页写进 `notes`，页数不一致直接抛 `AssertionError`——备注与交付的讲稿永不打架；不要在 build2 里再抄一份 SCRIPT，那是同一份内容维护两处、改一处漏一处的来源。

导出后跑 `scripts/verify_deck.py` 做机器自检（方括号残留、页数、16:9、备注、红字上限一次出结果），再过一遍人眼渲染图——脚本查不出「卡片底部空一块」「孤字换行」，见 `references/style-rules.md` 的「卡片与图位的实测尺寸」。

## 九、没有用户模板时：用默认模板

用户没给模板、只说“做个 PPT”，就用 `assets/default-template.pptx` 当底，**不要从空白新版式**：

1. 拷一份出来当工作稿：`cp assets/default-template.pptx <项目>/deck/默认壳.pptx`。
2. 它只有 4 页：封面（72pt 计划名 + 28pt 项目名 + 汇报人条 + 单位时间）、目录（左蓝栏 + 八项单列）、成果页（左右两卡 + 中间图 + 浅底说明条）、结束页。
3. 内页按内容选用 `scripts/merge.py` 与 `scripts/lib.py` 的组件，页眉编号 26pt，配色与壳一致（主色 `#003195`）；红判断句、卡片和结论条均非必选，不为用组件而补内容。
4. 壳里的四页只换文字与图片（按位置/文字内容找形状，**不靠固定索引**——壳是真稿抽出来的，索引已变），封面/目录的旧文案照着改成本项目的。
5. 想换成别的学校：只改 `brand/logo_blue.png`、`brand/logo_white.png` 与封面上那行单位名。

造壳命令（从任意一份成稿抽四页）：

```bash
$PY scripts/make_default.py 成稿.pptx 输出壳.pptx
```

## 十、常见返工点（都是踩过的）
完整十六条见 `references/pitfalls.md`（用户改过的文件如何增量改、「标题页太挤」指目录、封面只删重复、字号 16、批量删形状误删、颜色参数只吃 hex、编号框宽度、卡片不加分隔线、模板组织图整组删、删形状后索引错位、多列卡越界、ASCII 引号、表下说明段叠字、图注按框高算位置、行内强调词被折行、批量改调用点漏改）。

- 用户说「字要填满框」→ 提字号 + 压条目，不是加行距。
- 用户说「标题页太挤」→ 通常指**汇报提纲页**，不是封面。
- 用户说「用 GPT 生图」→ 立即生，不要再用色块拼一张凑数。
- 用户说「不要花颜色」→ 只留蓝白灰 + 红字强调，示意图用真实色。
- 用户改过的文件**不要整份重建覆盖**；内容合并按用户指令执行，未涉及页面原样保留。
- 评审要求压缩 → 先按指定映射合并，再删重复阐述；不要默认实验方案必须保留四页，也不要默认研究不足与关键问题必须放在同页。保留五项创新等必要条目，探索性内容继续标明性质。
- 用户说「最后一面问题有点大」→ 指**结束页**：模板原生文本框常是一段左对齐、一段居中，别用 `set_text` 修，整段删掉重绘（感谢语 44pt + 副句 30pt + 细分隔线 + 单位时间）。
- 模板的「单位时间」「汇报人」这类单行短文案可能带字符间距（`spc`），`set_text` 会把它一起继承，渲染成字间距拉开的怪行；凡是单行短文案，**删掉重画**，不继承原 run。
- 封面汇报人胶囊通常偏窄：加长文字（如补「教授／讲师」）前先加宽 group 的 `left/width`，否则“指导教师”会被折成两行。
- 用户说「正文重要词/句子/数字要用红色」→ 逐段人工指定标记，别跑自动挑词；尾条上的红换成亮一档的 `#FF6060`。
- 多列等宽卡片（步骤卡、四栏对比）**先算 `n*w+(n-1)*gap ≤ 12.5 in` 再摆**，别边放边加；越界只在缩略图上才看得出来。
