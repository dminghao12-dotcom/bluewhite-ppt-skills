# 把用户已经做好的整份 PPT 重排成 skill 风格

## 什么时候用

用户发来一份他自己做完的 `.pptx`（开题、中期、结题、组会、答辩），说“按你们的风格重做 / 好看点 / 多点图”，但不是给母版。给母版的走 [custom-template-deck.md](custom-template-deck.md)，这里是把**内容照搬、版式重做**。

## 开工前必问的三件事（一次问完，不拿默认值硬做）

重排旧稿最容易返工的不是排版，是这三个大局判断。用一次提问（agent 有提问／澄清工具就用它，没有就直接文字问）把三项一起问清（推荐项放第一）：

1. **配色**：沿用原稿的主色 / 换成我们一贯的蓝白 / 用户另给一份“配色参考”的模板。第三种的判据是“X 不用改，只是颜色参考这个”，此时**只换 THEME 色号，版式不动**（做法见 SKILL.md「风格库与扩展」，色号从参考稿渲图像素里量）。
2. **图的范围**：真实素材（论文插图、显微照片、数据图、截图）保留原稿的，只换 AI 味插画；还是全部换新；还是全部用重画的。
3. **页数**：原稿页数、原稿 +1、还是允许拆到 1.5 倍。

三项里任何一项答错都要整份重做——用户会先看到配色不对、再看到页数变多、最后发现论文插图被换成示意图，一轮里连发三条修正。

**用户已经在需求里答掉其中一项时，只问剩下的，不要复述一遍**：他把“要墨绿色一点”“该生图还是生图”写进需求，就只剩页数要问；给的页数不明确而且原稿很厚（40 页以上）时，按“贴近原稿”的默认值直接开工并在交付说明里写出页数变化，比停下来问一轮更符合他的节奏。

## 三条硬约束（先确认，默认按下表）

| 约束 | 默认值 | 落地方式 |
|---|---|---|
| 内容不大改 | 判断与数字一字不动，只压措辞 | 长句改到每条 ≤12 字；被压掉的细节全部进讲稿 |
| 参考文献不改 | 编号、题名、DOI 原样 | 只分割页与字号（12.5–13.5 pt，比正文小是规范） |
| 图分两类 | 真实素材（论文插图/显微照片/数据图/截图）保留原稿；发光 3D 渲染、彩色渐变大图这类 AI 味插画换掉 | 保留的图从原稿 pptx 里按位置取出来（`shape.image.blob`），AI 味图位交网页端 GPT 重画或换原生组件 |

**页数默认贴近原稿**：原 9–10 页就做 9–10 页，最多拆一页。18 pt 正文装不下时先合并同主题页、压措辞；只有用户说了“可以拆页 / 要更详细”，才做到原稿的 1.5 倍（19 页 → 21–23 页）。默认按 1.5 倍拆，用户会回“不用分这么多页，基本按原来的页数或者微调”，然后整份重做。

## 用户说“图片去 AI 化”时

先把原稿的图分两类，再动手（不分就白干）：

- **真实素材 → 一张不换**：论文插图、显微照片、数据图、平台截图、论文首页。这些换成重画的平涂示意图等于丢信息，用户会说“这个图还是按原来的”，并把原版式一起要回去。
- **AI 味插画 → 换**：发光 3D 渲染、彩色渐变大图、带光影的 AI 插画。

| 原稿那张图在讲什么 | 换成什么 |
|---|---|
| 机制、结构、界面、状态对比（自旋中心、配位体系、相分离、网络密度、四步制备） | 网页端 GPT 重画，一图一事、独立画布；图里不要数值，标签逐条对回原稿 |
| 表格、样品编号、工艺参数 | 原生 `table`（数字要能编辑、能核对） |
| 流程步骤、机理分期 | `steps_v` / `stages`，措辞逐字取自原稿 |

同一份稿子先发 4 张定风格，之后一句“这 4 张风格对了，继续按同一套语言再出 N 张”就能整批沿用（实测第二批 5 张一次可用），不要在每批里重新描述画风。取回后逐张核两件事：语义关系对不对（四步是不是真的四步、并行组有没有被画成串行），图里有没有自造的中文标签和数值。

## 步骤

1. **留档**：`cp 原稿.pptx source.pptx`，新目录里建 `images/`、`out/`。
2. **逐页 dump**：用 python-pptx 遍历每页的 `text_frame`，连位置一起打出来（`L/T/W` in），据此判断每页是几栏、几条、有没有表或图。这一步决定拆页，别凭缩略图猜。
3. **定新页序**：原稿一页讲两件事时才拆，**总页数仍贴着原稿**——拆一页就在别处合回一页；缺图的页补图；技术路线、实验流程这类“原稿只有一流程条”的页补一张阶段表（措辞取原稿正文，不新增研究内容）。
4. **搬备注**：写 `apply_notes.py`，用 `MAP = {新页序号: 原稿页序号}` 一页页映射，新加页手写一条；末尾 `assert len(prs.slides) == len(MAP)`。原稿备注通常写得不错，重写反而丢信息。
5. **取原稿的图**：先在原稿里按 `shape.top/left` 列出所有 `shape_type==13` 的图片位置，连尺寸一起打出来，按卡片/栏位对上年份或章节再 `shape.image.blob` 存盘（命名带年份或主题，例如 `y2016.png`）；不要按遍历序号命名，原稿里常夹箭头、Logo 之类的小图。AI 味插画才换新（网页端 GPT，取回后裁掉它自带的标题条）；流程、层级、对比表用原生组件。
6. **建 `build.sh`**：`PPT_FONT_SIZES` 那行写在最上面，链为 `prep_figs → dense_deck → apply_notes → spec_audit → lint → render → notes_docx → PDF`。
7. **逐页看图**：`has empty` 警告集中在哪几页，就补内容或换版式，不要靠缩字号消警告。

## 原稿自绘的图形读不出内容时

原稿里常有一整块是**图片或 SVG 画的时间轴／流程图**（`shape_type==13` 但 `shape.image` 抛 `no embedded image`，文字层里只有页标题和结论条）。这种页不能照搬，也不能猜内容：

- 按同一页的标题、结论条与相邻页正文，把它重建成本机可控的形态——时点链用 `table`（时点｜状态｜关键指标｜观察重点），流程用 `steps_v` / `process`，排除法用一条 `note` 写公式式的关系。
- **只写正文能证实的时点，中间缺失的留“—”或不设该行**；不要为了表格整齐补造 06:30、07:15 这类原文没有的时间点。
- 需要精确到分钟、又要整页当大图时，本机用 PIL 自绘一张 PNG（见 SKILL.md「配图分工」），不要交网页端 GPT——它会把时点或标签写错。

## 原稿里的坏页与母稿页码

- 文字溢出画布外、或与前页内容重复的页直接删，并在交付说明里写明哪一页、为什么删（用户默认认可“删掉坏页、其余全部保留”）。
- 原稿角落的 `P3`–`P17` 这类母稿页码不带进新稿。页码跳号说明这份是从完整稿里截出来的：交付说明里列出缺哪几页，并问要不要按同一套版式接着排。
- 章节名（研究背景 / 研究思路 / 实验方案）照原稿保留，用每页的 `"section"` 写进页眉（见 SKILL.md「参考稿只有页眉值得保留时」），不要另造一套章节体系。

## 参考文献页怎么排

- 20 篇一页放不下：拆两页，标题写「参考文献（1/2）」「（2/2）」，每页 10 篇两栏。
- 每条 = 题名 + `\n` + DOI，`size` 12.5–13.5，region 设 `valign: "top"`（默认居中会在上下各留一大块白）。
- 不要压到 11 pt 以下：lint 的 error 阈值是 11，`body` 警告阈值 12，参考文献用 12.5 刚好不触发。
- 结论条写一句“全部 DOI 已逐条核验”，正文里不要再标来源。

## 正文放大（18 pt 档及以上）后的版式适配

| 现象 | 处理 |
|---|---|
| `section` 每条要点 0.85 in > 框高 0.58 in | 要点压到 ≤12 字；辅栏宽 10 列以内时更要短 |
| `process` 流程条在 9–12 行大区域里只占 0.9 in，下面半页白 | 配「阶段 / 动作 / 产出」表；或改 `info_table_fig` 让表承载流程 |
| `timeline` 块高 0.66 in，`head` + 2 条就溢出 | 进度页改用表格（阶段 / 时间 / 工作 / 产出） |
| 三栏页每栏 3 条仍空 30%–40% | 每栏补到 4–5 条；仍空就换 `info_three_strip`，把口径类信息挪到 `bottom`；**再空就给该区域加一行 `foot`（深色底条，一句话）**，它比缩字号、比补套话都自然，也和页底总结条分工清楚（底条写这一栏的后果／本例，总结条写全页判断） |
| 四格页（`info_quad`）每格只有一句标题 + 两行说明，文字顶在格子上半部 | 给四个区域都写 `"valign": "middle"`，说明块在格内居中；日志仍报 `has empty` 是内容高度差的提示，看图确认居中即可 |
| “护理计划 / 方案对照”这类左窄右宽页，左栏只放一条 `note`（诊断 + 相关因素）时空 60%+ | 左栏 grid 从 5 列拉到 6 列，并在 note 下补 2 条 `markers`（观察重点 / 相关风险），措辞从该页的护理措施里提炼；右栏保持“目标 kv + 措施 + 评价”三段 |
| 同一个 4.95 in 主区里塞三节 `section` | 实测三节 × 三条 over-full 1.2 in、三节 × 两条也 over-full 0.7 in。要么压成两节 + 一条 `note` / `foot`，要么给该区域写 `grid` 覆盖加高；不要靠把每条压到更短来硬塞 |
| 原稿的“边界”写成“不虚构…” | 改正面写法：“只做软件与数据侧 / 不接实体传感器”，否则命中免责红线 |

## 版式种类按内容页数提前分配

`spec_audit` 按 `layout` 字符串数种类，**不写 `layout` 的页在统计里是 `None` 这一类，不论几页只算 1 种**；内容页 15 页要 8 种。排大纲时就给 `info_big` / `info_three` / `info_three_strip` / `info_split` / `info_split_strip` / `info_table_fig` / `info_hero` / `info_focus` 各分到页，不要等审计报“版式种类 7 < 8”再回头拆页。`info_big` 页的图还要显式写 `"role": "big"`，否则报“P04 大图解读页没有标 role”。

## 交什么文件

用户只要求“美化 / 重排”时，交 PPTX + PDF 两份，结尾问一句要不要逐页讲稿。不要因为 SKILL.md 默认三件套就替他编一整套 Word 讲稿——原稿没有可用备注、用户也没要求时，讲稿是白做功。

**但用户说“严格按我们的 ppt-skill 做”时按三件套交**（PPTX + PDF + Word 讲稿）：那句话等于把 SKILL.md 的交付标准一起授权了，重排稿也不例外；讲稿从页面内容重新写成完整书面句，不要搬原稿备注了事。

## 交付说明要单列的三项

1. 哪几页的图是新生成的、哪几页是原生组件（用户会拿这一节核图）。
2. 参考文献“一字未动，只分割页与字号”。
3. 措辞压缩的 2–3 条对照（原句 → 现句），让用户确认没有删掉信息；再列出需要他自己填的空（姓名、导师、日期）。
