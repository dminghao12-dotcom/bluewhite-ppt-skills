# 竞赛 / 创业答辩（BP 型）

适用：创新创业、揭榜挂帅、技术样机比赛及各类路演。先区分商业计划型与技术验证型：商业计划按评分表组织；用户给定逐页框架时，建立“原框架位置｜成品页｜唯一任务｜评分项｜证据来源”映射，保留页序和技术—验证配对，仅在明确允许处拆页。下文BP页序只用于没有指定框架的商业路演，不替换用户框架。

## 一、先把评分表拆成页面清单

例（AI+创新创业）：创新性 20 / 市场分析 15 / 产品可行性 20 / 商业模式 15 / 营销 10 / 财务融资 10 / 团队 10 / 附加 5。

- 20 分的维度配 3–4 页，15 分的 2 页，10 分的 1 页；封面与结束页不算正文。
- 交付回复里给一张“页 → 评分项”对照表。用户能拿它自查，被评委追问时也知道翻回哪页。

## 二、20 页 / 10 分钟的页序（实测可用）

1 封面 / 2 汇报安排（`numbered`，6–7 项）/ 3 执行摘要（`info_hero`：场景图 + 三个判断）/ 4 三个趋势（`info_three_strip` + 数据口径 `kv`）/ 5 痛点表（`table` 6 行）/ 6 竞品表（`table` 5 行：类别·代表·解决了什么·缺什么）/ 7 用户画像 + 市场规模（`info_split`）/ 8 产品流程（`info_stack`：六步 `process` + 目标函数 + 状态对象）/ 9 架构（`info_full` + `layers`）/ 10 关键算法（`info_three_strip` + 各自输出的 `kv`）/ 11 评测指标表 / 12 对照组实验（`info_three_strip`：A/B/C + 实验设计条）/ 13 原型进度 + 界面图（`info_split`）/ 14 商业模式（`info_split`：价值主张 + 收入结构表）/ 15 财务与融资（`info_table_fig`：三年表 + 柱图）/ 16 营销（`info_three_strip` + 定价 `kv`）/ 17 团队（`info_grid`：角色表 + 优势与机制）/ 18 风险与应对（`info_compare`，4 类各 1 条要点）/ 19 总结（`info_rows3` 三句话）/ 20 结束页。

## 三、合规红线

- 先读取本次赛事文件，确认是否匿名；只有明确禁止时，才从作品、视频和PPT移除学校名称、校徽、指导教师，并检查`meta.institution`、`brand`及背景图，防止模板泄露身份。赛规未要求匿名且用户明确要求保留标识时，提取并使用提供的原始标识，不凭其他赛事惯例删除；若二者冲突先确认。
- 页面上不写“待补”“来源：材料 §五”这类改稿痕迹；页码走字段，不写死。
- 财务与市场数字全部标“商业假设 / 估算”，并写口径：哪一年、什么来源、按多少渗透率。评委能问住的就这三项。

## 四、技术样机的证据审查

在排页和生图前，建立内部口径底稿，逐项记录“指标｜测试对象与条件｜样本与分母｜计时起止｜原图/正文/代码是否一致｜允许表述”。底稿留在项目目录，不默认增加对外交付附件。

1. 分开模型训练验证与整机穿戴实测，分别标注样本来源及正确次数/总次数；用脚本复算总准确率，不能把同一测试者的重复试验写成多人泛化或临床验证。
2. 逐项标注推理、稳定显示、事件确认和通知的计时起止；窗口积累与门控不能省略，不与竞品紧急呼叫倒计时计算速度倍数，因为起点不同。
3. 对照原图与实验方法核实载荷范围、循环次数、浸水/洗涤条件；保留真实曲线，不补画缺失测试点，不把短时浸水升级成机洗认证或长期耐久性。
4. 原报告流程图也要沿箭头核验，并与算法正文/代码交叉检查。明确传感输入、硬件预处理、模型部署端、规则判断与显示支路；发现图文冲突时先纠正，不能因为“原图”就照搬。必须精确对应信号字段且后续要改时，使用原生可编辑矩阵或结构图；生成图纠错后仍逐条复核通道数量、标签与箭头。
5. 将已实现功能、待对照验证指标、拟扩展功能分开；已受理申请不等于专利授权，预期论文不等于发表，团队自评成熟度不等于第三方认证。
6. 成本表用脚本复算分项与区间上下限，分开样机采购成本、规模化估算、售价及经营费用；不以制造成本低于竞品零售价推出已实现利润。
7. 未提供原始数据文件时，明确统计值取自报告，不声称独立复算；源材料的矛盾在底稿与讲稿中保留处理依据，页面采用可证实口径。

## 五、财务页

- 收入 / 成本 / 净利都用区间（保守–乐观）：表里给区间，柱图给区间中值并写明“区间中值，商业假设”。
- 原生 `chart` 的负值必须显式 `min`（默认 0 会把亏损柱裁掉），取整十倍数（`min: -50` 才是 -50/0/50… 的刻度）。
- 融资额与用途比例放结论条，不单开一页。

## 六、产品界面图

- 竖版手机界面在 16:9 里上限约 4.4×5.0 in（去掉 `lead` 才有 5.0 in 高）。图上带 6 组以上小标注时投影读不出来：要么裁掉标注列只留屏幕，要么让生图端出**横向三屏**（输入 / 方案 / 风险），横向能铺到 6 in 以上。
- 图注写“界面结构示意（非最终设计稿）”，别让评委当成已上线产品。

## 七、材料是一本项目书 / BP 时：图源与演示节奏

用户同时给“一份项目书 PDF + 一份参考 PPT”时，参考稿只取配色与气质（见 SKILL.md「风格库与扩展」），**内容与图全部从项目书里挖**，不要生图补概念——项目书里通常已经有平台截图、架构图、案例数字，它们比 AI 插画更能过评委追问。

取参考稿配色不要目测：`soffice --headless --convert-to pdf` 把参考稿首页与一张内页转出来，`pymupdf` 渲成 PNG，再用 PIL 取页眉、标题带、底条三块区域的众数色（`Counter(im.crop(box).getdata()).most_common()`），得到主色与深色两档；然后在 `scripts/theme.py` 里加一档 THEMES（如 `bank`：主色 `#0B4A92` + 层阶向蓝绿 `#1475A2` 过渡），`build.sh` 里 `export PPT_THEME=<档名>` 跑全链。只改色号表，不动 `info_style.py`，版式仍按本 skill。

取图与排版：

1. 先把 PDF 文本全量导出到 `src/full.txt`（`page.get_text()` 按页拼），再按“背景 / 痛点 / 产品设计 / 技术 / 页面演示 / 商业模式 / 案例”切段，逐段标出可成页的唯一判断——项目书的章节目录就是大纲底稿，不要另起一套。
2. 平台截图用内嵌图直接导出，不要截屏：`page.get_images(full=True)` 取 `xref`，`pymupdf.Pixmap(doc, xref)` 存 PNG（实测 1000–1600 px 宽，投到 7–8 in 宽仍能读出表头）。架构图能自绘的就自绘——四层结构、8 个模块这类术语必须逐字与正文一致的地方，原生 `matrix` 比截图里的橙色/绿色配色更贴主题。
3. 竖长整页截图（宽高比 0.8–0.9）不要塞 `info_big`：裁顶部 KPI 行 + 主图成 1.8–2.5:1 的横图（`crop((0, y0, w, y1))`），完整长页只作素材。裁切上沿要对准 KPI 卡片顶边——低一点切掉卡片标题，高一点把页面上方的彩色横幅/导航条带进来，两种都得重渲复看，别只信一次裁切。
4. 一页一图，图注写清“上/下/左/右各是什么”，并把关键数字（指数、贡献度、AUC）同时写进页面正文——投影上谁也读不清截图里的小字，数字必须在文字里出现一次。

页序（22 页实测，18–22 页区间的竞赛稿）：封面 / 汇报安排 / **场景页**（`info_big`：一笔真实业务的三天动线图 + 三条读数）/ 政策与客群（`info_three_strip` + 口径 `kv`）/ 五处卡点（`info_table_fig`：痛点表 + 卡点↔模块映射）/ 产品定位（`info_split`：是什么-解决什么 + 首页截图）/ 总体架构（`info_full` + `matrix` + 五项输出 side）/ 业务流程（`info_grid`：`steps_v` 六步 + 四岗分工）/ 数据与指标体系（表 + 清洗口径）/ 模型 A（公式 + 指标表）/ 模型 B（表 + 规则 side）/ 模型 C（大图 + 象限 side）/ 融合分级（公式 + 权重 + 三档）/ 演示 1–4（建档 / 价值评估 / 风险穿透 / 授信辅助，每页一截图 + 3 条读数）/ 模型效果（ROC + 混淆矩阵 + 指标）/ 创新点（`info_four`）/ 实施路径（`timeline` 四阶段）/ 价值与推广（三栏 + 部署口径）/ 结束页。

- 演示企业的那几个指数（基础价值 / 生命周期 / 修正后价值 / 信用风险 / 综合指数 / 阈值 / 构成拆解）在演示页里各出现一次就够，不要在另一页再列一遍全表——同一批数字讲两遍是竞赛稿最常见的注水。
- 材料里没有人员信息时不要造团队页：封面留“项目负责人”空行，交付时说明“缺人员信息所以没做团队页，给我姓名/年级/指导教师就补一页（会挤到 23 页，可同时合并两页模型）”。
- **开头用一笔业务的场景页，不要用政策页开场**：用户说“整体要讲好一个故事”时，第一内容页写“某企业提交贷款申请后，经办人在 N 个系统之间的三天”，把痛点直接打断在这条动线上；政策与客群退到第二页做支撑。场景页 = 一张动线图（每段标“作业 / 中断”）+ 侧栏“三天的产出（一份报告、无可比指数、口径随人而异）”，比先摆政策数字更快让评委进入问题。
- 场景页讲的是哪家企业，后面的“案例企业”总表就删掉：演示页已经用同一家企业走完整条链路，再列一张全表就是同批数字讲两遍。用户嫌“没讲好故事”往往不是缺页，而是有重复页。
- **生图里不许出现任何数值**：网页端会自己编一套贡献度、评分、百分比（实测给过 78/100、42%、35%、23%），构图再对也不能进竞赛稿——评委一问口径就穿。需要读数的位置用项目书里的真实截图或本机数据图；定点返工只发“只改数值、构图与标签冻结”，仍不干净就换回真实截图并在交付说明里写清。
- **“图丰富一点”= 把文字栏换成判断关系图，不是加截图**：四栏并列、三栏要点、原生 `timeline` 这类“一排文本框”的页面，整页换成一张讲同一件事的大图（判断依据错配、四层递进、四阶段路线各一张），侧栏只留 3–4 行短说明。实测这样一换，四栏栏首不齐、底部空一块、时间轴留白三个问题同时消失；反过来继续在栏里塞图标只会被同一句话再打回。

## 八、内容取舍

- 首页只回答“谁、在什么场景、比现有方案强在哪”，不堆功能清单。
- 每页结论条给一句可被追问的判断（“可行率 95% 是硬线”），不写“具有重要意义”。
- 团队页主动写短板（学生团队、缺全职投入、缺行业资源）；评委一定会问，先说比被问出来好。
- 还没有实测数据时不要用 `chart` 编曲线，改用 `matrix` / `table` / `kv` 排结构，图注标“规划值”。
- 竞赛稿的讲稿按路演语速 250–260 字/分估：22 页落在 3800–4000 字约 15 分钟。用户没有给时长时要主动报“这一版约 15 分钟，若是 8–10 分钟我按删页不删字重排”，不要默认交付一版时长未知的稿子。

### 竞赛稿的语体：名词化、机构口径（用户会反复追加“学术一点 / 专业一点 / 术语化一点 / 官方一点”）

收到这类要求时**不要逐词润色**：按下面这张表把标题、要点、表头、图注、结论条、讲稿六处一次过完。页面与讲稿必须同批改——只改页面，下一轮还会被同一句话打回。

| 口播 / 初稿 | 竞赛稿口径 |
|---|---|
| 贷前调查的三天 | 贷前调查的作业周期 |
| 五处卡点 | 五处制度性卡点 |
| 信息分散 / 数量虚高 / 口径不一 / 静态评价 / 黑箱输出 | 数据源分散 / 数量指标失真 / 计量口径不统一 / 时点截面评价 / 结果不可解释 |
| 把评分工具变成贷前作业工具 | 创新落点在于将评分工具改造为贷前作业工具 |
| 让客户经理少跑几个平台 | 跨平台检索与手工整理显著减少 |
| 结论说不清、复核不了 | 结论的可复核性不足 |
| 看得见、算得出、查得清 | 画像完整、指数可比、来源可追溯（这类三连整稿最多一次，且不进标题） |

- 判断用名词化陈述，不用“让……”“不是……而是……”：`输出作为人工审批的辅助依据`、`不改动银行既有授信制度`、`成本集中在口径校准与结论的可复核性`。
- 术语表（照用，不为好懂换白话）：风险正向 / 风险型指标、区分度、稳健性、可复现性、可追溯性、辅助决策工具、授信质询、风险缓释、全链路穿透、修正强度、经验分布阈值、时点截面、口径校准、区分度与稳健性。
- 讲稿同批换开头：口播式（“先看一笔业务”“下面用一家企业走完流程”）改成“首先是……”“以下以……为例完成全流程演示”；表格的“影响”列也一起术语化，不要只改标题。
- 术语统一是硬约束：同一指标全文一个叫法（知识产权价值指数 / 综合风险指数），页面、图注、讲稿三处必须逐字一致；用户提出统一词表时按词表全稿替换，不要只改他点到的那页。
