# 配图细则（生图通道、分工、图位、压图、裁切）

> 本文件由原 SKILL.md 正文迁出（内容未删减），主文件只保留摘要与指针。

#### 3. 配图（详见 [visuals.md](visuals.md)）
- 用网页端 ChatGPT 生图，**不用本机生图模型**（显存不够会卡死电脑）。**配图只有一个通道**：不要改用 agent 内置的生图工具（如 `image_generate`）或任何其他生成工具——用户把任何非网页端的生成都视为“又在开本地模型”，会直接发火。网页端临时连不上（代理握手失败、页面 `ERR_CONNECTION_CLOSED`、CDP 无响应）时，先修浏览器与代理再重发；修不好就如实说“图没出来、等恢复再补”，不换通道、不拿别的模型凑。提示词写“这张图说明什么 + 画哪些具体对象和关系 + 图位比例 + 逐字给出的标签”，不替 GPT 定画风。
- 取回后逐张看：主题对不对、机制画没画出来、有没有 AI 味；不过关就重画，网页端自判废的变体不充数。**风格不搭也算不合格**：稿子里已有 5–6 张灰阶论文原图、版式是蓝白信息图时，第一批常给成商业海报质感（高饱和绿、真人美颜脸），贴上去与相邻页完全两种语言。判废重画时把**用途**说清楚——“放进哪一份稿子、同稿另有 N 张灰阶论文原图、要学术信息图那种平涂矢量感”，它自己就会换；仍然不要指定色号、线宽。
- **图里的每个标签都要对回源材料，不只是对画风**：时间跨度、纪/期名称、分组数、原文数字都是硬事实，模型会按常识补一个“看起来对”的名字（实测：265 Ma 的研究里，栖息地三格被标成“早古生代 / 中生代 / 新生代”，而研究范围根本没有早古生代）。取回后逐条看标签，能核的都核一遍，再决定贴不贴。
- **错一处只发一条定点返工指令，不整张重画**：写清楚“第几列哪个标签错了、错在哪、改成什么”，再补一句“其余结构、箭头、配色、图标保持原样，只重出这一张”。实测一轮就能只动标签，整张重画反而会换构图、连对的部分一起漂。
- **稿子换了主题色，图必须跟着换**：校内 VI（深绿）或紫白主题下，生成图往往还是蓝灰调，贴上去像外来截图。只要求换主色、其余冻住——“保持构图、比例、层级和所有中文标签完全不变，只把主色换成本校 VI 的绿色系”，一轮就能过；换完仍逐张对一遍标签，确认没有被顺手改错。
- **分组图逐条沿箭头核验起点和终点**：药理条件、浓度或处理时间属于并行比较时，各组都必须有明确的分装来源与汇总去向，组间不出现暗示串行或联合处理的箭头。不能仅凭“三列看起来并列”判通过；局部放大检查跨列细线和箭头。纠错图也要重新沿线核验，防止模型只是删除跨列线，却把所有分支都接进第一组的不同时间点；出现这种残留构图时换干净生图会话重画，不从错误图裁块补救。
- 还没有的图在图位写 `prompt` + `aspect`：生成时导出到 `images/*.prompt.md`；`prep_figs.py` 把缺图降级为占位框，先排版后补图。**GPT 图没拿到就留空图位（用户 2026-11 定）**：流程 / 结构 / 机理 / 架构示意图不要本机自绘来“补空”（PIL、matplotlib、原生形状拼图都算自绘），也不要为了消灭空框换成别的组件；空图位保留 `label` 与 `prompt`，交付回复里逐个列出页码和 `images/*.prompt.md`，等用户或网页端补图。只有用户明确说“这页不要图了”，才改用不需要图的原生组件——`matrix`（要素 × 构成 / 难点）、`info_compare`（方法对照）、`info_three_strip`（三条设想 + 底部 `kv`）、`steps_v`（四步流程）。

**讲课 / 汇报稿的图不是“锦上添花”，而是默认配置**：机制、通路、病因路径、分型、分期、流程、闭环这类内容，默认配一张网页端 GPT 的机制图/流程图，放在左栏、要点放右栏；连续两页以上纯文字（只有小标题条和要点）就要回头检查是不是该出图。图与文各占一半时，4:3 页给图 5.2–5.6 in 宽，16:9 给 6–7 in。

**运动与康复类小插图按小图片规划**：用户所称“矢量图”可能指参考稿中的平涂／等距人物插画。先看实际画面及其页内作用，将运动人物、康复动作、测量设备等作为小图片嵌入相应分区，默认零文字，不升级成整页大图，也不代替研究框架或精确测量时间轴。按研究对象与动作选图，多图围绕不同内容配置，不用无关运动图标凑数量；方法图须符合实际动作、器械与保护要求。需要SVG／EMF／可编辑路径时再核验文件及PPT对象类型，不能把矢量风PNG宣称为真矢量，也不能仅因它是PNG就放弃用户要的小插图效果。

**图注要解释图例，不只写图号**：图里的颜色、符号、虚线代表什么必须写进图注（“蓝＝未采摘，红＝采摘；左雨前、右雨后”），否则读者只能猜。用户明确提过“图标需要解释”。

**指标、化学式的下标不能省**：CODMn、NO3-N 这类要么用真下标（baseline run，见踩坑清单），要么在正文注明写法，不要留成普通小写字母。

**配图分工（GPT 优先；用户 2026-10 原话「以后你优先让gpt帮你画，不要自己画」）**：

| 图的用途 | 谁画 | 为什么 |
|---|---|---|
| 概念、流程、角色、状态（检测/隔离/切换/重联、边界、三层、数据流、充放电……） | 网页端 ChatGPT，沿用既定科研风，每批默认四张独立画布，按实际缺图数提交 | 小批便于逐图核验主题、比例与标签，且不承载具体数值 |
| 定量对比（成本高低、SOC 轨迹、误差分布、日负荷曲线） | 本机 matplotlib，图注写“示意数据” | GPT 画不出定量关系，硬画就是编数据 |
| 必须精确到分钟的时点链（救治时间轴、事故/处置时间轴） | 本机 PIL 自绘一张 PNG（仅限 ≥6:1 的页底超宽条；`ImageFont.truetype` 中文黑体，画布按图位比例定，卡片上下交错） | 时点、标签一个都不能错，GPT 会改写成“看起来对”的时间 |
| 系统架构 / 单线接线 / 分层控制 | 网页端 ChatGPT，一页一张大图 | 关系复杂，要的是它自己判断构图 |

**流程 / 架构 / 分层页默认整页交网页端出大图，不要先用 pptx 形状手绘**：用户说“画图丰富一点、用大图替掉文字”时，第一反应是把这几页送去生图，不是自绘。**默认一律先交网页端出图，本机自绘只留两个例外**（用户原话："合适的你不要自己画了，你优先用gpt生图美观又方便"）。自绘只用于：① **图位是 ≥6:1 的超宽条**——页底的个案处置链、休学断点链、时间线，一条横贯 12.4 in、高 1.2–1.5 in，生成图没有这个比例，硬缩成 16:9 再裁会把节点文字切掉；② **顺序即论点、错一位整页作废**的节点链，且必须逐字术语。**"图里的术语必须逐字与正文一致"不构成自绘理由**——把逐字标签清单原样发过去（"中心写 A、内圈写 B、外圈五段顺时针写 C/D/E/F/G"），中文标签它一次就能写对，还自带人物插画与暖色氛围；拿这条当借口把十几张概念图全部 matplotlib 自绘，交付后会被整份退回重做。实测 6 个节点、每节点 2–3 个中文短标签的结构图（状态向量→LSTM→权重/方差→K 个组分→条件密度；6 子网络→等权平均→综合后验→三类输出）它一次就能画准，别拿"标签多"当绕开生图的理由。自绘的图统一按**最终插入尺寸 1:1 出图**（`figsize` 就是页上的英寸数，字号即投影字号），暖色系走 `#8C3112 / #B24A1E / #C9663A / #FBEDE1`，与 GPT 插画同色才不打架。选 GPT 大图时把公式、训练配置这类必须精确的内容留在图外用原生组件排（图下一行公式 / `kv` 条），两边各承担一半。

四条硬规则：

1. **先算净图位，再按比例生图**：大纲阶段就把每个图位的净宽×高（扣掉图注框、栏首小标题）写进需求，生图时直接给“最终 3.8×2.4 in、画布约 8:5、主体占 75%–85%、至多 2 个短标签”。给 16:9 再大幅裁切必然出现“宽框里一张邮票”，也会切掉主体；比例不符就按图位重画，不要用 `fit: "cover"` 掩盖。
2. **插画里要读的标签 ≥ 3 个，格子宽度给到 3.5 in 以上**——放不下就换 `info_three` / `info_four` 让图占整栏，不要缩图；`rows` 行里图只有 2.4 in，只配零文字图形。
3. **默认保留完整画布**：按图位比例生成的图只做等比缩放和压色，不裁切；旧素材有独立标题条时，仅在不损伤主体、比例和标签的前提下去掉。主体过小、长宽不合或图内文字过密就按图位重生，不靠截取复杂图的一角补救；论文原图裁子图仍按原始来源规则处理。
4. **交付前适度压图，先保可读性**：普通插图可降到约 1200 px 宽并量化 200 色；高密度大图保留 1600 px 或原尺寸。压缩不改变画布比例，压后按最终投影尺寸检查标签和细线；保留未经修改的原始素材与哈希。**插画多的稿子把 PNG 转 JPG 再入库**：十几张 GPT 插画按原 PNG 贴进去，PPTX 会到 17 MB 以上（单张 1.5–2 MB），邮件与投影都吃力；长边 1600、`quality=90, subsampling=0` 存 JPG，同一份稿降到 3–4 MB，投影上看不出差别，原 PNG 另存 `images/png_orig/` 备改。**论文原图的半幅裁片同理**：18 张 250 dpi 的灰阶裁片按 PNG 塞进去是 15 MB，压到长边 1800、`quality=92` 的 JPG 后整份 6.6 MB，投影下病理与荧光图没有可见差别；转完把 `content.json` 里的 `images/*.png` 一并改成 `.jpg` 再重建，别只生成了文件不换引用。插画自带大片米白 / 浅色底的，`trim_margins.py` 和按角落色取的 bbox 都裁不动（底色不是纯白、内部也没有可裁的边）——别在这上面连试两轮，要更满就让网页端按更紧的构图重出。

5. **图位小于 3 in 时不要画带坐标轴的图**：2.6×1.5 in 的缩略图位里塞刻度、图例、轴标签，投出来每个字只剩 5–6 pt，等于没画。改成无轴 sparkline——只留走势线 + 误差带 + 两个角落标注（`负荷（kW）`、`0—23 h`），语义交给图注（“前期模型逐时拟合，误差约 10%”）承担。**带中文标签的框架图放进 4 in 左右的框图位时，无论谁画都要按这个净尺寸定字**：交网页端就在提示词里写死“画布约 4.1×2.3 in，每框只一个 2–4 字标题，不写其他文字、不加副标题行”；本机绘制则 `figsize` 直接取 4.1×2.3、框标题 9–10 pt、每一行小字都删掉。按 6 in 画布画好再缩进 4 in，等于把 9 pt 变成 4 pt——这类“每框两行小字”的框架图曾是本机返工两次的主因。

**图偏小时先去掉盒式图注、再谈放大**：`caption_style: "box"` 先吃掉 0.45–0.9 in 高度，同一图位实测图宽因此少 10%–25%（2026-10 实测：核磁页 5.4→6.8 in、门水平页 7.0→8.7 in、结论机制图 7.8→8.75 in）。把图号并进相邻 `section` 的 `head`（如 `甲基化结果（Fig. 4）`），或改成图下一行 12.5 pt 灰字 `para`，图就能按区域高度撑满；用户说“图都可以大一点”时默认按这条整页重排，不要靠调字号或留白凑。

**结果页的标准结构是「图 + 三段解读」**（用户原话「你每个图肯定是要解释的」「重要的多解释，简单的可以少解释」）：图占上方 8 行通栏（上半 / 下半并排），下方 4 行放三个 `note`——`怎么读`（子图对应关系、坐标、显著性标记）／`看到什么`（原文数字）／`说明什么`（作者结论或对我们的启发）。重点图每块两行、次要图一块一行；标题带已经写了判断句时**删掉 `lead`**，否则 lead + summary 吃掉两档高度，三段条只剩 1.2 in 会报 over-full。三段条按 17.5 pt 自动缩一档，比正文小、比图注大，正好。

**期刊竖长多面板图（宽高比 0.7–0.95）在 16:9 上塞不进一页**：按行切成上下两半，各占一栏并排铺满通栏（每半约 6 in 宽，接近印刷尺寸），分别标 `原文 Fig. N 上半 / 下半`。执行上有三条硬要求：
  - **切口要在“全宽”上都是空白**才成立。只按右侧 60%–65% 的空白带选切口，左侧那列柱状图/图例仍在原处，一落刀就把标签切成半截（实测残字“B”只剩一撇）。做法：先算全宽的行墨迹剖面取最稀行，再回到渲染图确认切口两侧没有断字；`< 0.005` 的窄带才是可用缝。
  - **切不出干净缝时不要硬切满图**：免疫荧光列贯穿整页高、面板上下交错的图（每行都有内容横跨左右）没有可用的横向缝，任何一刀都会切掉半行图像。这种图改成整页 `info_big` 放**整张**原图、数字写侧栏，或按论证分组只取 2–3 组子图并把子图号写进图注；不要为了“看起来大”切出一堆半行细胞图。
  - **两半放进 `row` 时 `widths` 写各自宽高比**（`[1.41, 2.35]`），不要写 `[1, 1]`——等分会把窄的那半塞进宽格子、四周留大片白，反而比整张缩着放更难看。
  切完把两半拼成一张检查图过一眼再进稿；若某半的下沿露出下一个面板的残字，把该半裁短 10–20 px 即可。

**框架 / 架构类大图的提示词要给「字量上限」，不只给标签清单**：把每个环节的细节（反应式、能量值、面板说明、年份）写进需求，它就会全部画进框里，投到 8.9 in 宽的页上框内字只剩 8 pt，投影读不出。一页框架图只要求“每块一个短标题 + 最多一个关键数字”，细节留给页内文字与讲稿；第一版明显塞满时按这个口径重出一张（新开会话比在原地重试快），而不是把图缩到通栏了事。实测重出一版只留标题与 `600 mV / 1 A cm⁻² / 120 h` 后，同样宽度下标签才真正可读。

需要整理旧素材时使用 `scripts/prep_gpt_figs.py`；它默认去白边并裁标题，不能把它当作保留整幅画布的默认压缩器：

**只裁白边、不裁标题条用 `scripts/trim_margins.py`**（生图插画贴进 PPT 前的默认整理器）：按灰度差阈值找非白 bbox，加 1.2% 内边距，保留完整画布与图内全部标签；批量输出 JSON 摘要，`--dry-run` 先看尺寸再决定是否写文件：

```bash
$PY $S/scripts/trim_margins.py images/raw/ --out images              # 批量裁白边
$PY $S/scripts/trim_margins.py images/ --out images --dry-run        # 只报 原尺寸→裁后尺寸
$PY $S/scripts/trim_margins.py a.png --out images --thresh 7          # 浅蓝衬底要保留时
```

```bash
$PY $S/scripts/prep_gpt_figs.py 原图.png --name g-detect --out images   # 去白边 + 裁标题条 + 压图（默认就裁）
$PY $S/scripts/prep_gpt_figs.py 对照图.png --name g-point --split       # 一张左右对照拆成两张
$PY $S/scripts/prep_gpt_figs.py 原图.png --name g-keep --no-cut-title   # 主体靠上、裁不得时
$PY $S/scripts/prep_gpt_figs.py images/raw/ --out images                # 批量，文件名即输出名
```

**零文字小图标的素材表不走这两个脚本**：图标表要按行扫白缝裁、再按亮度抠成透明（否则贴到带底色的行／浅紫条上是一个白方块），配方在 `chatgpt-web-planning` 的「零文字小图标走素材表例外」；`trim_margins.py` 只收 bbox，不做透明。

两个容易踩的默认值：**不加 `--out` 会写回源图所在目录**；**裁标题条是默认行为，没有 `--cut-title` 参数**。`--no-cut-title`只关闭裁标题，不保证保留白边和原画布。新图已按图位比例生成时，直接用 Pillow 的 `convert('RGB') → thumbnail((max_w,max_h), Image.Resampling.LANCZOS) → quantize(colors=200) → save(..., optimize=True)` 压缩，不调用 `crop`；保留原图及哈希供核查。不要用固定裁切百分比处理不同图片。

**按用户最新确认，默认每批四张独立图片**，不必固定拆成两张；每张独立画布，不拼版。只剩一两张缺图时按实际缺口发，不为凑四张重复生成。网页端实际限制、混题或拼版时再降为两张或单张恢复。每条写“用在哪页 + 唯一判断 + 图的用途 + 净图位宽高/比例 + 图内文字密度”，构图和美术细节交给网页端。先核对独立画布，再接入PPT。若批次被拼成总览、反复复现旧主题或只给样品照片，立即停止该失败批次，换干净会话按单图或两图重试；不要在长失败上下文里反复追加整份图单，也不从判废拼版中裁图充数。**它自报「已整理成 N 张独立 PNG」并列出文件名时，页面往往只渲染出其中一部分**（实测 4 张只渲染 2 张）：先滚到底、再 `location.reload()`，重新枚举 `img`；**`naturalWidth == 0` 不等于没生成**——同一批图常在轮播里留几个 0×0 的占位 `img`，blob URL 本身有效，直接 `fetch(src) → 8192 分块 btoa → 700k 切片读回` 就能拿到完整 PNG，落盘后 `PIL.load()` 验真；只有 fetch 也失败才按单张补发一句；不要因为看到一张 2×2 预览就判它没给独立图，也不要顺手把那张预览裁开当成品。
