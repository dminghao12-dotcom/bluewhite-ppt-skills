# 文献精读页：从一篇论文到一版组会 PPT

适用：组会 / 文献汇报，精读**一篇方法论文**（运筹、调度、算法、模型类）。综述或“一次讲三篇”不走这套页序。

## 一、页序（16–18 页，15–20 分钟）

| 页 | 任务 | 首选页型 |
|---|---|---|
| 1 | panel 首页：左深蓝栏，右侧居中标题与元信息，下方论文首页 3:2 裁片 | `scripts/paper_cover.py` |
| 2 | 论文信息卡 + 为什么读 + 一页结论 | P15 / `info_split` |
| 3 | 研究背景：现实场景 + 单厂假设 + 文献缺口 | P02 双栏 |
| 4 | 定义与复杂度：公式、解空间、定理 | P01 + `formula` + `table` |
| 5 | 论文框架：问题刻画 / 方法 / 实验三条线 | P09 三栏或 P04 |
| 6 | 方法一：模型或问题刻画 | P09 / P10 |
| 7 | 方法二：模型结果或主算法 | P04 / `info_table_fig` |
| 8 | 方法三：规则、参数、实现细节 | P02 / P05 |
| 9 | 方法四（可选）：第二个算法或流程 | P04 / `steps_v` 原生流程 |
| 10 | 实验设计：实例、指标、统计方法 | P10 对比表 |
| 11 | 小规模结果：能否解到最优 | `info_table_fig` / `info_hero` |
| 12 | 大规模结果：相对差距与耗时 | P04 大图 |
| 13 | 关键图精读：交互、边界、反常点 | P04 / `info_big` 左图右文 |
| 14 | 主要结论：三条，各带数字 | P12 结论行 / `info_full` + `rows` |
| 15 | 创新点与局限：左三条创新，右 3–4 条局限 | `info_split` 双栏 |
| 16 | 我的评价与可借用之处 | P02 `info_split` |
| 17 | 结束页：问题、方法、启发各一句 | 结束页 `points` |

页数按材料和时长删并：10 分钟版保留问题、框架、主算法、大小规模结果、结论/创新/局限、讨论；模型细节和实验设计各压成一句话。

### 机制 / 生物学论文的 10 分钟版（按老师给定的六段提纲）

场合常是老师直接给提纲：“背景与科学问题 / 科学假说 / 核心生化技术与实验设计 / 关键结果（3 min）/ 讨论：创新点、局限、与理论关联 / 总结 + 未来方向”。这时 15–16 页这样分：

| 段 | 页 | 版式 |
|---|---|---|
| 封面 + 汇报安排 | 2 | `paper_cover.py`；`numbered` 六项、20 pt |
| 背景与科学问题 | 2 | 分时期损失用 `info_three_strip`（三时期 + 底部 `kv` 数字）；已知与缺口用 `info_compare`（左已知、右未答，中间箭头写“缺口”） |
| 科学假说 | 1 | `label_rows` 四步一句一步（候选基因 → 顺式变异 → 上游抑制 → 下游代谢），下方一条 `note` 写验证顺序 |
| 核心技术与实验设计 | 1 | `table`：技术｜回答什么问题｜关键读出；几种处理条件放结论条或 `kv` |
| 关键结果 | 5–6 | 每页一张整图 + 三段读图；3 分钟按每页约 30 s 算，最多 6 页 |
| 讨论 | 2 | 创新与局限 `info_split`；与教科书理论的接口用三列 `table`（理论节点｜本文证据｜接得上的地方） |
| 总结 + 未来方向 | 1 + 结束页 | 综合大图 + 三段（链条 / 育种或应用价值 / 边界与下一步） |

- 结果页按因果链排序，不按原文 Figure 顺序：变异 → 基因表型 → 上游因子 → 直接靶标 → 代谢物 → 演化选择。听众跟得上的是箭头，不是图号。
- 3 分钟装不下 7 页结果时，把驯化/育种这类“证据补强”页并进讨论或总结，不要每页压到 20 s。
- 讨论的局限只写原文自己没闭合的推断（某结合未测、上游激酶是推测、田间单点），用“本文没有测”的写法，不把原文讨论段抄成局限。
- 讲稿按 240–260 字/分折算：10 分钟 ≈ 2400–2600 字；写完用 `notes_docx.py` 的估算核一次，超 1 分钟就把最长的两三页各删一句，不要整篇平均削。
- **图表特别多的临床 / 影像类论文，页数按面板数定，不按 16–18 页削**：一张 8–9 面板的大图按论证拆 2–4 页（每页一个图组 + 三段解读），五张正文大图加上框架、队列、方法、结论、评价，总页数落到 26–28 是正常的；讲稿按页均 200–250 字配（≈6,000 字、22–26 分钟）。不要为了压到 18 页把多面板图挤成 6 in 宽；只有三四张单图的方法论文仍按上表的 16–18 页走。

### 理论/博弈论文不要硬套算法实验顺序

- 先讲参与者、目标、信息和实际行动时序，再讲求解顺序。用一个有适用条件的最优反应推导例子，解释逆向归纳怎样得到上游需求；不要只列“建立模型—求解—分析”几个词。
- 按论文结构组织解析命题、经济机制、网络/策略变化与扩展。无算法和基准实例时，不凭空添加“数据集/运行时间/算法性能”页。
- 区分系统总利润、单个企业利润和产量；风险概率与成功概率、外生网络与内生关系选择都要定义清楚。同一结论在不同指标上可能方向不同。
- 原文定理中的网络序列配图不是编号 Figure；图注用“原文定理 X 配图”。保留某些中间结构可被跳过、反复切换只在特定参数区间成立的限定。
- 分别标明解析证明、数值例子和解释性推导。缺电子附录时不声称复核了全部阈值与证明；不照抄正文疑似笔误作为新结论。
- 宽网络序列/时间轴用通栏原图配下方短说明；多面板曲线图优先整图通栏或独占一页，不默认裁子图做左图右文。确需突出细节时，在保留整图的前提下另加局部放大；不能只剩局部而失去面板间比较。

### 生物学等实验类论文：按干预与读出组织

- 用“研究问题 → 总框架 → 样本与分组 → 检测指标 → 关键原图 → 结论 → 创新 → 局限”替换算法论文页序；不硬加复杂度、大小规模实例或运行时间。
- 在写页标题前建立证据表：`指标｜样本/实验单位｜干预及浓度｜处理时间｜组内时间比较｜同时间组间比较｜图表号｜结论边界`。区分生物学重复、技术重复与检测到的细胞数，不能把技术重复或细胞事件数当独立样本量。
- 逐指标核查抑制剂与刺激的交互：某项运动学响应被阻断，不代表膜电位、酶活性或所有读出均失去响应；摘要的总体概括不能覆盖正文明确列出的例外。
- 按图注解释大小写字母、星号等统计标记，分别判断时间比较和处理比较。正文说显著、表中字母却不支持时，记录两处原文及图表位置，讲稿说明口径不一致，页面避免给出无争议的显著性断言；不得自行修正源表字母或补算不存在的P值。
- 比较各时间点在不同指标上的响应，不用单一指标峰值宣布全局最优时间；均值上升、响应时间不同和单调剂量依赖是不同结论。区分ATP总含量与生成通量、活力比例与运动速度、机制参与证据与直接靶点证明、体外指标与受精能力。

### 材料 / 器械类论文：按“筛选—改性—表征—体内—功能”组织

- 页序：问题与现有手段 → 材料筛选（候选从哪来、用什么指标筛）→ 为什么原候选不行 → 改性（化学/结构上到底改了什么）→ 物性表征 → 体内（成像 + 组织学）→ 功能（一两个应用各一页）→ 结论 / 创新 / 局限 / 评价。不要套算法论文的复杂度、实例规模、运行时间。
- 筛选页要写清“为什么是它”：候选范围（FDA 清单、商用材料）、初筛指标，以及“挡得住 ≠ 留得住”这类二次筛选——只报第一轮排名，听众会问它在体内能不能留住。
- 改性页把化学变化讲成一句可复述的话（“把可逆的质子化换成不可逆的结合水”），再用一张放大图支持；物性页让可测参数当主角（黏度、pH 响应、离子强度），并说明它怎么变成工艺参数，不要罗列仪器。
- 体内页必须同时给有效性（成像/功能读数）和相容性（组织学、体重、腹泻等），缺一半听众就会追问另一半。
- 局限页优先写“没做的模型”和“没说的时间尺度”（只有健康动物、只做了 6 天、剂量偏大），再补材料本身的安全性（例如含铝）。原文没讨论的批评要标明是讲者补的，不冒充原文结论。
- **电催化 / 电解槽这类器件型论文**：性能页按「阳极活性 → 界面证据（表面 pH、原位光谱）→ 机理（计算 + 示意）→ 对侧电极 → 器件」走，四张原图正好四页。**「同一指标下与已报道体系的对照表」是否单出一页要看前面**：背景页已经用三条路线（PEM 纯水／碱化海水／天然海水）对比表时，这张表与它三行重复，不再单出，把“性能对标 PEM、流程免淡化免加碱”这句位置判断挪进器件页的结论条；背景页没摆路线表时才单独补一页。这样 15 页的分配是：封面、汇报安排、论文概况、路线对比、研究框架图、设计推理链、四张原图、结论、创新与局限、评价、结束页。器件页只报三个数：目标电流密度对应的电压（**必须带温度**）、稳定运行时长、法拉第效率；其余参数进讲稿。同一篇里常出现两个“200 小时”，分别属于两电极恒压与三电极归一，页面要分开写、不要合并成一句。

## 二、动笔前先做四列笔记

每篇论文先拆成四列，不要从摘要抄：

| 问题 | 方法 | 证据 | 边界 |
|---|---|---|---|
| 它把什么扩展成了什么？为什么难？ | 模型怎么建、算法怎么搜、关键规则是什么 | 哪些表/图回答“有效吗”，哪些回答“为什么” | 假设、目标、规模、实验条件 |

每页只写一句判断，标题就是这句话；证据页的数字必须能在论文表/图里指回去。

## 三、论文数字先复算，再上屏

- 解空间、实例数、运行次数、RPD、相对提升，能用公式或表复算的全部复算一遍。
- 正文数字与公式/表对不上时：**页面用可验算的例子，把疑点放讲稿**，不要把疑似笔误当结论。
- 论文摘要与方法的计数可能不一致（例如“14 个启发式”其实是 12 个构造式 + 2 个 VND）；按方法节拆开说，讲稿里点一句口径。
- 只报均值不够：小规模看 %最优 / GAP，大规模看 RPD；有 ANOVA / HSD 的，明确“数值低”与“统计显著”是两件事。
- **图上的星号与正文 p 值可能不一致**（图 2 把 Δ 标成 `*`，正文写 p=0.060）。页面按正文讲（写“边缘显著”），图注照图的符号写，讲稿里点明这条口径；不要为了两边一致去改图的标记，也不要把边缘显著写成确定结论。
- **标定曲线上的 R²、斜率、检出限，抄图内公式，不凭印象**：同一篇里不同面板的 R² 并不相同（实测同一篇的乳酸标定 0.996、Randles–Sevcik 线性 0.998、pH 标定 0.995），写成同一个数，图注和插图当场打架。上屏前逐张放大读方程；正文没给、图上有的，按图写并在讲稿里说明取自哪张图。
- **同一指标在正文与汇总表给两个区间时，全稿统一取汇总表**：实测正文写发射功耗 2.6–4.8 μW、Table II 写 1.25–3.4 μW。页面取表值（其他页也在引这张表），并在功耗页的侧栏加一段「两处口径」写清两处不一致、讲稿里点一句“按正文的 0.8 V 条件理解”——不要两页各用一个值，也不要在交付说明之外悄悄改掉。
- **引用 index 与 SE 前先看两者是否自洽**：SE 比 index 还大、又和给出的置信区间矛盾，多半是排版笔误（实测 index=0.146、SE=0.226、CI[0.064,0.950] 三者对不上）。页面只引 index 与 CI，不引 SE，把疑点写进交付说明。

## 四、从论文 PDF 取图（pymupdf）

```python
import pymupdf
doc = pymupdf.open('paper.pdf')
pix = doc[pno - 1].get_pixmap(clip=pymupdf.Rect(x0, y0, x1, y1), dpi=300)
pix.save('images/fig8.png')
```

- 先用 `page.get_text('blocks')` 找 “Fig. N.” 或 “FIGURE N” 的 caption，图通常在 caption 上方；结合 `page.get_images()` 与 `page.get_image_rects(xref)` 定位完整图的显示范围，不仅按图注列宽猜边界。
- 多面板原图可能由一张主图和多个独立的小位图面板字母叠加组成。此时用 `page.get_pixmap(clip=主图显示矩形,dpi=260或300)` 渲染PDF区域，保留页面上的叠加标记；不要只用 `doc.extract_image(主图xref)`，否则可能丢失A/B/C等标记。同一xref可在一页出现多次，按其显示矩形与目标图号匹配。裁片边界可留少量安全白边，但须检查没有混入相邻正文。
- **裁完必须用 vision 看四边**：y 轴标签、旋转的算法名、时间轴、图例都容易被切掉。宁可保留一点白边，也不要切字。
- **上沿先量再裁，别按“多留 12 pt”估**：论文正文常紧贴图顶排版，clip 的 `y0` 多留一点就会把图上方那行正文（“From the perspective of the four major regions…”）一起裁进来，而白色 bbox 收紧不会把它去掉——它是黑字，算“内容”。做法是先渲整页，按行墨迹找图的上沿（与找下沿同一套 `ink.sum(axis=1)`），再以该行减 2–4 pt 作 `y0`；或者干脆先大范围裁、用 `getbbox` 收紧后逐边看图里有没有整行句子。
- **改裁切之前先打开源图确认缺陷真的在图里**：渲染预览上看着“y 轴前导 0 被切”，多半是 1601 px 预览缩到 800 px 后的显示问题——源图里 `0.45` 是完整的。先 `vision` 看 `images/figN.png` 本身，再决定要不要重裁；否则会连续重裁两次拿到同一尺寸（实测两次都是 1169×867，因为 bbox 左缘已经贴着最左的墨迹），白费两轮构建。
- 用 PIL 的 `ImageChops.difference` 去白边，再去掉 caption；不要用固定百分比裁。
- 竖长的多序列比对只能截部分行时，图注写“部分代表毒株”，不能写“全部 N 株”。
- 图注保留原图号（“图 8 …”）；数据图保持原色，不重绘。伪代码、决策树、流程框图可以重绘成原生形状，但要在交付说明里写清“按 Fig. X 重画”。
- 原本是两个独立 Figure 的对照图可分别取图（如两条规则各自的甘特图）。如果属于同一 Figure 的 (a)(b) 面板，则优先完整保留两面板，不为套半栏而拆开。
- **上一张图的图注会跟着混进下一张的裁片**：同一页上下叠两张图时，`y0` 取两图间距的一半常落在上一图图注的末行上（实测 Fig. 15 的裁片顶部带进 Fig. 14 图注的“across multiple data rates. (c) …”，而缩略图上看不出来）。上沿按**上一图图注块的 `y1` + 2 pt** 定、下沿按 `caption.y0 - 1` 定，不要按间距或百分比估。
- **L 形面板组不能一次裁矩形**：3+2 布局（上排 a b c、下排 d e，右下角是另一张面板 f）时，矩形框要么切掉 c、要么带进 f——实测按 x 到 400 裁就把 c 整块丢了。按行分别裁（上排一行、下排前两格一行），再用 PIL 拼到同一张白底画布（行间留约 30 px），图注仍写 `原文 Fig. 2a–e`；不为凑矩形丢面板，也不要保留 f 的空白缺口冒充“原样”。
- **`get_image_rects` 与肉眼看到的位置对不上时，按整栏渲染量比例**：实测流程图的 rect 只覆盖了它的一部分，按 rect 裁出来是半张图。把该栏（如 x 290–595、y 40–320）整体 200 dpi 渲染出来，在 vision 里量出图在画面中的相对位置，再换算回 pt 定 clip——比继续猜 rect 快一轮。
- **整页一张大位图（Wiley / Elsevier 常见）直接按像素裁，不走 `get_pixmap(clip)`**：判据是 `get_images()` 每页只有一张、显示矩形覆盖整版心（宽 ≈520 pt）、位图宽 1900–2100 px。这时面板字母与坐标刻度都画在位图内部，`doc.extract_image(xref)` 拿到的是完整整图，300 dpi 渲染反而是插值放大 1.5 倍。用 `Image.open(...).crop((x0,y0,x1,y1))` 按墨迹缝的**像素**坐标分面板，省掉 pt→px 换算一轮。
- **面板字母会被墨迹阈值吃掉**：`rows = (gray<235).sum(axis=1); rows < 3` 这套空白判据把只有两三个暗像素的面板字母行也算成“空白”，按缝裁完，a/b/c 就不在片子里了（实测每张下排裁片都丢了本行字母）。要留住字母，`y0` 取到缝的上沿再向上让 2–3 px；不留就靠图注写 `原文 Fig. 2d` 定位，不要在图注里自称“整图”。

### 多面板图按论证分组分页（面板边界靠墨迹空白定位）

一页 16:9 能给的宽度有物理上限：0.7 左右竖长的 9 面板整图放进 `info_big` 只有 3.5 in 宽，面板字母和轴标签投影必糊。这时按**论证任务**（机制示意 / 主要性能 / 可靠性）把同一 Figure 分成 2–4 组、每组占一页，图注写清包含哪几个面板，**全部面板都要出现**——不丢面板就不算拆图，也不必逐页征求同意。

1. **先打印面板边界，再裁**：`rows = (np.array(gray) < 235).sum(axis=1)`，`rows < 3` 的连续 8 px 以上空白即行间缝；列方向同样用 `sum(axis=0) < 2`、连续 10 px 以上。把这两组 run 打印出来按缝裁，比目测稳。注意「横轴标签」与「下一行面板」之间常夹一段有墨迹的区域，真正的缝比预想的窄。**缝隙列表只是候选，不能直接当行界**：一条图里混排行宽（3+2、3+2、4、2、1 这类五带布局）时，面板内的浅色带也会让整行显白，实测同一张图同时给出 765–770 与 802–817 两个相邻候选，按错的那个切就把下一行面板切掉一半。做法是先按 350–450 px 步长把整图切几条试片、各缩到约 1000 px 宽用 vision 读面板字母，确认行界后再正式裁——两轮读图比返工便宜。
2. **裁完先看宽高比，再谈字号**：0.7 上下的组只能进侧栏或竖槽；**3.5:1 以上**的横向条带用 `info_focus` 通栏才能吃到 11–12 in；**2.2–2.8:1 的组在 `info_focus` 里高度受限，只有 7.3–8.0 in 宽**（9 行主区约 3.7 in，扣盒式图注后剩 3.2 in），改 `info_big` 得 8.6–8.9×3.4–3.6 in，或删 `lead` 把高度让给图；两张并排的组（各 1.2–2.7）放 `info_split` 各 6.3 in 刚好。
3. **下沿最容易带进下一行的面板字母**：实测按 381–742 裁 d–f，图底多出半行 `g h i`，缩到 733 才干净；左上角也可能带进上一组的字母。逐张 `vision` 看四边，别只看缩略图。
4. **落盘用语义名**（`fig3cde` / `fig4top` / `fig5abc`），图注写 `原文 Fig. 3c–e`；同一 Figure 的两组落在相邻两页，不算重复用图。
5. 三组以上的条带（宽高比 ≈3.8）放 `info_big` 只剩约 2.3 in 高，改 `info_focus` 或 `info_split_strip`，让图占满宽度、文字进底部条。
6. **两张 1.3 左右的方图不要并排放进 `info_compare` 两栏**：半栏 5.8–6.3 in 的槽是 2.5:1 的形状，1.3:1 的方图按高度算只有约 2.8 in 宽，两侧各留 1.5 in 白，看着像漏排。要么一张图占一栏、另一栏全放文字（`info_split`），要么两张拼成一张 2.6:1 的通栏图；宁可撤掉这一对，也不要并排两张小方图。

### 按行墨迹分带批量裁（Nature 系 Extended Data 页必用）

- **Extended Data 的图注可能排在图中间，不在整图下方**：常见版式是 a、b 并排在页首、图注块夹在 a/b 与 c 之间、c 独占下半页。按「图注上沿 = 图的下沿」裁 a/b，会把整行图注裁进片子里（页面上表现为“图下面多出一段小字”）；按「图注到页尾」裁，又把 c 切掉半截。判据：`get_text('blocks')` 里以 `Extended Data Fig. N |` 开头的块，若它的 `y0` 之上仍有面板（不是页首），这一页就是分段排版——**每段各裁一块，不要用一个矩形框住整页**，分开的两块可以分别放到框架页与方法页。
- **带边界用行墨迹找，不靠目测**：150 dpi 渲染整页 → `ink = (a < 235).sum(axis=1)` → 打印所有 `< 8 px` 且连续 ≥4 行的空白 run，即面板之间的缝；按缝的中点定 band，两端各留 3–5 px 余量。px→pt 用 `pt = px * 72 / dpi`（150 dpi 即 ×0.48）。
- **先给宽 band，再让白边 bbox 收紧**：band 只负责“不带进邻居”，留白交给 `ImageChops.difference(...).point(v>10)` 的 `getbbox()`；反过来先压紧 band 再裁，轴标题和右下角图例十有八九被切。
- **验证要在接近成稿的尺寸下看**：把 4–8 张裁片拼成 1300–1500 px 宽的检查条逐张读，别用 900 px 的总览图——缩到那个尺寸，“轴标题被切一半、只剩半个面板字母、图注残行”全都看不出来（实测据此判“干净”，贴进 PPT 才发现底边横排图例缺了半行）。
- **最常见的三种残留**：① 上一行面板的横轴标题（`False-positive rate`）留在裁片顶端；② 下一行面板字母 `e`/`f`/`h` 或下一段正文标题落在底边；③ 正文图注整行（`Fig. 3 | Extended validation…`）跟着进来。逐个把 `y0`/`y1` 往里收 3–10 pt 重裁，不要靠修图擦掉。

### 只给到附件（Supporting Information）时

- **判据**：第 1 页是 `Supporting Information for …`，下面列 `Supporting text / Figs. S1 to S13 / Tables S1 to S2 / Legend for Movie S1 / SI References`，页脚 `1 of 23`；正文只有 Materials and Methods，没有摘要、引言和结论；图号一律 `Fig. S1`。PNAS / Science / Nature 系的附件都是这个版式。
- **不要就着附件硬讲**：附件讲的是“怎么算的”，不是“为什么算、算出什么结论”。先用标题 + 第一作者搜到主文（这类刊大多开放获取，机构库、作者主页常有 PDF），`curl -x <本地代理> -o main.pdf <url>` 落盘后用 pymupdf 读正文前两页——研究问题、两种体制这类框架句、结论段的量级数字都在那里。走网页抽取常拿不到 PDF 正文，落盘再解析最稳。
- **分工固定**：框架与结论按主文写，机制、参数、所有具体数字与全部图按附件写；图注标 `原文 Fig. S3`（**保留 S**，不冒充主文 Fig. 3——虽然附件里的 S3/S5/S6 往往就是主文 Fig. 3–5 的底图）。第 2 页（汇报安排）的备注里说明一句“材料是论文附件，正文我另找了公开版”，交付说明单列一节写清哪部分是我补的。
- **交付时两份 PDF 都进 zip**（`SI_Attachment.pdf` + `Main_Article.pdf`），文件名仍用 ASCII。
- **附件图的三个特点**：① 常见“一页一图 + 图注紧贴下方”，裁切框下沿取图注块的 `y0 - 3`；② 工作流图（Fig. S1 这类）多为矢量路径，`get_images()` 只返回几个小位图，按页面坐标渲染再裁白边；③ 图框常顶到版心边界（左侧约 52 pt，比正文 72 pt 更靠外），`x0` 取 40–45 pt 才不会切掉最左那个框的边框字。
- **附件里的 Fig. S1 是“五段式”工作流**，不是整篇研究框架图；仍要另生一张框架图（重建 → 变量 → 模型 → 栖息地 → 产能 → 校核）放在背景之后，两者各占一页。

### 纯矢量插图（Nature / Science 系排版）：从图注上沿反推裁切框

- **判据**：`get_images()` 只返回一两个小位图（HAADF-STEM 插图、比例尺图标、刊头 logo），而整页明明有两行三列的面板——插图画的是矢量路径，`get_image_rects` 给不出范围，按 xref 取图只会拿到那几张小图。
- **做法**：用文字层定位图注，`b = [x for x in page.get_text('blocks') if x[4].strip().startswith('Fig. 3 |')][0]`，取 `b[1]`（图注 top）；裁切框下沿取 `y1 = b[1] - 1`，上沿从页眉下方（约 y=40）起，左右用版心（约 26–570 pt），300 dpi 渲染后按白边 bbox 收紧 12 px。
- **下沿宁可从 caption 反推，不要目测**：多面板图最下排的横轴刻度与轴标题最先被切掉；按目测高度裁，b、d 两个面板的 `Time (h)` 会没掉，而缩略图上看不出来。
- **尺寸校准**：这类图在期刊版面上占满版心（约 7 in 宽），投到 16:9 上 6.2–7.2 in 已经是 0.9–1.0 倍印刷尺寸，不必追 10 in 以上——再大就要牺牲侧栏或结论条，得不偿失。
- **图注块在页首（y0≈49）＝插图在上一页**：说明这一页以图注开头、图在本页之上。这时对**上一页**做行墨迹扫描找下沿，不要拿本页图注的 y0 当裁切参照：`ink = (np.array(gray) < 230).sum(axis=1)`，在页面 40% 高度以下取最宽的一段连续空白（150 dpi 下 ≥40 px）的上沿作 `y1`。只按整页高度裁会把正文两栏一起裁进来（图高只剩 0.7 的竖长比例就是征兆），裁完四边仍要肉眼过一遍。

### 扫描版 / 无文字层的 PDF（整本期刊扫描件、部分 SSCI 刊）

- **判据**：`page.get_text()` 每页都回 0 字符，但渲染出来正文清晰可读（正文是整页矢量图或 Type3 字形）。不是 PDF 坏了，也不用先去找外部 OCR——渲染 + vision 逐页读是最快的路。
- **做法**：`page.get_pixmap(dpi=150)` 存 PNG，按 4–6 页一批用 vision 读。每批读完立刻把「样本量 / 平台 / 交互 F / ηp² / 中介指数与 CI / 各单元格均值」抄进证据表，不要指望回头再找。
- **插图照样好取**：`page.get_images()` 只返回图块本身（正文文字不在图块里），`get_image_rects(xref)` 给显示矩形；按矩形外扩 8–10 pt、300 dpi 渲染即得干净的整图，不用裁正文。
- **统计量必须回原页裁片核第二遍**：扫描件上小号数字首读常错一位（χ²=39.37 读成 39.57、φ=0.45 漏掉）。凡要上屏的数字，放大原页确认一次再写进 JSON。
- **推算出来的数字要标明**：由百分比 × 单元格数反推出判断次数（81+17=98、37+61=98，而 98 = 49 名被试 × 4 类刺激，合计 196 次判断）不是原文直接给的。表注与讲稿都写“按 Table 3 推算”，别让它看起来像原文的样本量。

## 五、论文图在页面上的取舍

- **纯文字页补一张概念对比图**：研究背景、现有手段对比、论文信息卡这类没有原图可用的页，交网页端画一张概念示意图（例如“减重手术 / 内镜套袖 / 口服涂层”三种介入方式并排），比三行文字更快建立直觉；图注写“（示意）”，不冒充原文插图，也不承载任何数据。

- **完整原图优先于版式偏好**：用户要求论文大图尽可能不拆开。含多个面板的大图先整体放置，再决定用通栏、独占页或减少旁文；“左图右文”不能成为裁掉面板的理由。强调某一子图时仍保留整图，另加局部放大并对应原面板号；确需只留子图须先向用户说明原因并获得同意。
- **全篇研究框架必查**：先区分论文中的研究对象网络、单步方法流程与整篇研究架构。没有整篇总框架时，交网页 ChatGPT 原生生图补一张，用少量短标签讲清研究问题、方法/比较分支、结果评价与扩展的关系，图注标“根据论文整理的研究框架示意”。核对生成图中的决策时序、变量含义和结论条件，不把漂亮但错误的总图上屏。
- **机制示意图不算整篇框架**：原文常已有“局部碱性微环境”“电荷转移”这类单点界面示意（Fig. 3d / Fig. 4e），它讲的是某一步为什么成立，不能替代“从问题到器件怎么走”的总图。两张各占一页：框架页紧跟背景页（听众先知道问题，再看地图），机制页留在结果之后。用户会直接点名要这张图（“合适的地方可以让 gpt 生图啊比如框架图”），把它当必做项，不要以“原文已有机制示意”为由跳过。
- **框架图的语义验收三条**：并列分支（阳极／阴极、两条验证线）不能被画成先后步骤；每个环节的标签要能在原文找到对应小节；图里出现的数字只放原文给过的（能垒、电压、时长），不放推断值。图注写“根据原文整理的研究框架示意”，不冒充论文原图。

- **0.84–0.9（竖长）的多面板图**：16:9 上受高度限制只能到约 4.0–4.4 in 宽（印刷 7 in 的 60%），这是物理上限，不要为凑尺寸裁子图。做法是给 `main` 写 `grid: [0,10,0,12]`、`side` 写 `[10,14,0,12]`：竖图填满 5.2×5.7 的竖槽，而不是在 8.9 in 的宽格里居中当“邮票”；14 列的侧栏约 7 in 宽，放 3 段 + 一条 `kv` + 一个 `note` 都不挤。三段竖排（0.84）实测图只有 4.2 in 宽、面板轴标签投影上读不出：关键数字全部写进侧栏与讲稿，图只作视觉锚点，交付说明里写明这一页“看形态不看数”“面板字母偏小，讲的时候直接指 b、c 两格”。
- **主图多于页数时按“画面主体 / 配套证据”二次分配**：同一批动物、同一批数据里与主图成对的“动力学 / 对照”图（主图是 bouton 形成、配套图是同批动物的体积时程）不单独占页，把它们的关键数字写进主图页的侧栏与讲稿，并在交付说明列清“9 张里选了 6 张、另 3 张作为配套”。15 页稿子每张多面板图单占一页，9 张就要 18 页左右；宁可少放图页，也不要把多面板图压到 4 in 以下。
- **面板 >6 个、或整图在幻灯片上宽不满 7 in 时，加一页放大**：整图页保留（第一遍讲清结构），下一页只放大 1–2 个关键面板（图注写“Fig. 3a 放大”，原图不撤）。10 面板图压到 6 in 宽时，面板内标签只有 4–5 pt，投影必看不清；两页合计比一页塞完有效，也不算拆图。
- **整图可清楚容纳时，再考虑“左图右文”**：`info_big`（左 17 列原图 + 右 7 列三段）或 `info_hero`（左 14 列原图 + 右 10 列表/文字）；两图对照用 `info_split` 左右各一张。多面板大图优先通栏，不拆图；简单单图适合左图右文。避免在完整大图下堆大量说明，把图挤成邮票。右侧统一写“看哪里 / 看到什么 / 说明什么”，不要复述图题。
- **右栏只有 3.5 in 时只放两段**：`info_big` 的 side 是 7 列（约 3.5 in），三段各带 2–3 条要点实测会把内容顶到页面外（lint 报“超出页面边界 (9.61,7.32,…”）。删掉“看哪里”这一段，把要指的面板写进图注（“原文 Fig. 5；重点看 b–d 的剂量时机与 f、g / i、j 的对照”），右栏只留“看到什么 / 说明什么”，每条 ≤ 约 16 字、一行说完；要保留三段就把 layout 换成 `info_hero`（side 10 列）。
- **面板 ≥8、长宽比接近 1 的方形整图**：16:9 里受高度限制最多只有约 5.9 in 宽，面板字母和坐标投出来读不出。做法是同一 Figure 给两页——一页整图（保留全部面板，交代结构与流程），下一页单独放大信息量最大的一个面板；放大页用 `info_full`（图 + 底部一行 `kv`）能到 8.7×3.6 in，比 `info_focus`（9 行主区只剩 2.6 in 高）大一倍多。原图仍在整图页，不算拆图，图注写“Fig. 3a 放大”。
- **15 分钟内不加页时，方形整图怎么给足高度**：`info_big` 默认图高只有 4.28 in（页眉 1.55 + `lead` 0.72 + `summary` 0.72），1:1 的图就只剩 4.3 in 见方。删掉 `lead` 后图高到 5.0 in，再给分区写 `grid` 覆盖——`main` 写 `[0,12,0,12]`、`side` 写 `[12,12,0,12]`——方图填满左格（约 6.3 in 宽、5.0 in 高），右格 6.3 in 宽放三段小标题不挤；1.5:1 以上的图保持默认 17/7。实测：7 列 `side` 里每个 `section` 放 2 条要点刚好，再加第 3 条或一条两行 `note` 就 over-full（日志报 0.96–1.0 in）。
- **1.5–1.7:1 的单面板结果图（交互图、分组柱状图）：删 `lead`、留 `summary`**。图高被页眉 1.55 + lead 0.72 + summary 0.72 吃到约 4.2 in，盒式图注再扣 0.6 in，图只有 6.2 in 宽；删 lead、图注压成一行后实测 `info_hero` 到 7.15×4.46 in、`info_big` 到 7.86×4.97 in。侧栏本来就有“怎么读 / 看到什么”，lead 是重复信息；`summary` 要留，它承担这一页的落脚点。
- **侧栏只有 2 个 section 时会在中间露出大洞**：`valign: spread` 把两块推到上下两端，中间空 1–1.4 in。补一块真内容（`note` 写该研究的 D 值、两种匹配组合之间的差异、协变量是否显著），不要靠调 `gap` 或改字号填。
- **`info_side3` 的 s1–s3 是 4 行槽位（约 1.67 in）**：里面再套 `band` + `section` 会重叠（深蓝条压到正文上）。方图配三条解读时 s1–s3 只留 `section`（小标题 + 2–3 条一行要点），或整体换 `info_big` + `grid`；`band` 只用于通栏分区。
- **甘特图 / 均值图 / 交互图**：坐标清楚的，优先原图；甘特图两图对照用 `info_split`：左栏 `stack` 上下叠两张原图（各约 5.2×2.5 in），右栏写 Rule 1 / Rule 2 的区别；若并排更清楚，再用 `info_full` 自定义 `grid` 顶部 `[0,24,0,7]` 放两图、底部 `[0,12,7,5]` 与 `[12,12,7,5]` 放文字。`info_top_two` 的 top 只有 6 行，会把两图压成 3.6×1.7 in。
- **均值图 + HSD 区间**：`info_big` 主栏，方形图受高度限制通常只有 4.3–5.0 in；轴标签小，具体数值放侧栏表，不要指望听众读图上的算法名。
- **决策树 / 伪代码 / 大表**：不要整张投影。决策树改成“第一分层因素 + 2–3 条结论”的表；伪代码改 `steps_v` 四步流程；大表只留关键 4–6 行。**单栏竖长的算法流程图（宽高比 0.5 上下）也归这一类**：它只占单栏版心（约 110 pt 宽），放到 16:9 上受高度限制最多 2.6 in 宽、框内字约 6–7 pt，一律按原意重绘成 `steps_v` + 三条判据，讲稿与交付说明写明“按 Fig. X 重画”，原流程图不上屏。
- **算法流程**：用 `steps_v` 或 `info_split`，不要用 `cycle` 放需要读的步骤名——`cycle` 的环内文字在深蓝段上几乎看不见。
- **纯文字的三阶段框架**：用 `info_three` 三栏（band + section + note），不要用 `stages`；`stages` 不带图时文字沉在框底、上半空一大块。

## 六、讲述与评价页

- **收尾固定两页**：一页主要结论（3 条，各带数字），一页“创新点与局限”左右双栏（左 3 条创新，右 3–4 条局限）——用户明确要求把创新和局限并排放在一页，省一页且“做成了什么 / 没回答什么”一眼对照；不要把结论也塞进这一页，结论必须单独一页。
- 标题写成结论：“Model 5 最稳，n 是瓶颈”“小规模不显著，大规模 0.10%”，不要写“实验结果”。
- 关键图精读页只讲三件事：看哪里（坐标/图例/区间）、看到什么（数字/趋势）、说明什么（能支持到哪一步）。
- 局限页用 `info_compare` / `info_quad`：每条写“假设 + 影响/下一步”，不写“仍有不足”；创新点页用 P12 结论行，每条对回一个证据。
- 可借用点写方法学，不写“我们也能用这个算法”：两级决策、模型紧致化、统计评测这类可迁移的做法更稳。
- **机理论文多一页「证据对应表」**：行取一次论证的四到五个环节（中间体生成 / 迁移 / 加氢 / 副反应被抑制），列取「实验证据｜计算证据」。它把散在原位光谱、对照实验、DFT 三处的结论压到一页，比再加一张机理示意有用；放在 DFT 页之后、稳定性与器件之前，作机制部分的收口。每格写方法与数值（“ESR 信号强于对照”“界面到 Co 势垒 0.11 eV”），不写“相互印证”这类空话；最后一行的结论条才写“四条都对得上，才敢说是 A 而不是 B”。
- 讨论页给三个能当场回答的问题，问题要落在自己的课题上，不写“未来可以进一步研究”。

## 七、这一类的常见坑

| 坑 | 正确做法 |
|---|---|
| 把论文摘要翻成 15 页 | 按“问题—方法—证据—边界”重组；每页只回答一个问题 |
| 论文里的决策树/伪代码整张塞进 16:9 | 重绘成四步流程或 2–3 条结论；原图只留坐标清楚的 Gantt/均值图 |
| 裁图裁掉 y 轴、旋转算法名或 caption | 每次裁完用 vision 看四边；宁可留白边不切字 |
| 论文数字照抄，正文与公式不一致 | 先复算；页面用可验算的例子，疑点放讲稿 |
| 小规模均值低 0.3% 就下结论 | 看 HSD 区间是否重叠；不显著就写“数值接近” |
| 纯文字框架用 `stages` | 换 `info_three` 三栏，否则文字沉底、上半空白 |
| 流程用 `cycle` 放步骤名 | 换 `steps_v` 或 `info_split`；`cycle` 只放 2–4 字且生成后必看 |
| 贡献页写成“首次/填补空白” | 只写论文真正做的事；不能由材料支持的评价放讨论，不上屏 |
| 文献汇报把结论、创新、局限三者合成一页“贡献与边界” | 结论单独一页；创新点与局限合成一页左右双栏（左“做成了什么”、右“没回答什么”）；三者挤一页才会让“新在哪、差在哪”都看不清 |
| 文章原图放在通栏顶部、下面再堆三栏 | 原图用左图右文（`info_big` / `info_hero`），右侧写读图三段；通栏只适合 ≥3:1 的超宽图 |
| 10 个面板的方形 Figure 塞进一页，投影时面板字母读不出 | 整图页 + 一页放大核心面板（`info_full` + 底部 `kv`）；原图不拆，图注写“Fig. Xa 放大” |
| `info_big` 右栏写满三段，正文顶到页面外 | 右栏只留两段，把“看哪里”挪进图注；每条 ≤16 字，或换 `info_hero` 加宽右栏 |
| 文献汇报首页还是设计封面 | 没有单位模板时套 panel 首页：左 3.83 in 深蓝栏 + 右侧居中标题块，论文第 1 页裁成 3:2 放在标题下方；用 `scripts/paper_cover.py` 生成。**有 VI / 单位模板时反过来**：套模板的封面壳，panel 竖栏不用（见 custom-template-deck.md「四点半」） |
| 用户给了参考首页，还自创渐隐/倾斜/出血 | 先 1:1 复刻参考：位置、字号层级、图片大小、留白都照抄；参考图就是验收标准，只调对齐和可读性 |
| 替换第 1 页后旧论文页/旧底图还透在标题后面 | 先删 slide 的 `p:bg`（旧背景图）再画新首页；`paper_cover.py` 已处理，手写脚本要自己删 |
| 论文页 `resize` 到固定框，字被压扁 | 用 `ImageOps.fit` 从顶部裁 3:2（1800×1200），不拉伸；裁片宽 6.4 in、高 4.27 in |

## 八、论文首页封面（panel 模板 + 论文页 3:2 裁片，2026-10 用户定）

文献汇报 / 论文汇报的**第 1 页套用 panel 首页**：左深蓝栏“文献精读”+ 三行 tagline；右侧居中两行标题（中文题目 + 副题），一条细线，作者/期刊一行、日期一行；下方放论文第 1 页的 3:2 裁片（刊头、标题、作者、摘要上半页），**干净、完整可见**，不渐隐、不倾斜、不是整页截图。用户原话：“这样不就行了吗”。

```bash
$PY scripts/paper_cover.py paper.pdf deck.pptx \
  --title "分布式置换流水车间调度问题" \
  --subtitle "DPFSP：模型、算法与基准" \
  --meta "Naderi & Ruiz · Computers & Operations Research, 2010" \
  --tagline $'分布式车间\n多工厂调度\nDPFSP 的起点' \
  --date "2026 年 10 月"
```

- 论文页默认渲染 PDF 第 1 页，从顶部裁 3:2；已有 3:2 裁片用 `--image`。
- **整本期刊 PDF（前面带期刊封面、目次、英文目次）时，第 1 页不是论文**：直接把该 PDF 交给 `paper_cover.py`，封面会贴成一张“湿地科学与管理”刊头照。做法是先定位正文起始页（`page.get_text()` 里搜标题或 DOI），用 pymupdf 把那一页渲染成 PNG 再 `--image` 传入：
  ```bash
  $PY -c "import pymupdf; d=pymupdf.open('$PAPER'); d[4].get_pixmap(dpi=200).save('images/paper_p1.png')"
  $PY $S/scripts/paper_cover.py "$PAPER" "$DECK" --image images/paper_p1.png --title … 
  ```
  这个页码偏移对后面所有取图同样成立：`get_text('blocks')` 找到的页码是整本 PDF 的页码，`doc[p]` 直接用，不要再减 1 或按期刊页码换算。
- 图片宽 6.4 in、高 4.27 in，在右区居中，底边离页脚约 0.2 in。
- 标题/副题/元信息都居中；不要 kicker、不要大号单位地址。
- 生成后渲染第 1 页：论文页不能压左蓝栏，标题不换行，日期完整。
- `build.sh` 里要把 `paper_cover.py` 放在 `dense_deck.py` 之后，否则重建会换回设计封面。

## 九、用户说“有点短”，要扩页时

先分清两种反馈：**“讲不完”**是页多字多，按上文删页；**“有点短”**是内容单薄，页数与讲稿字数要一起涨，不能靠放慢语速或加过渡句撑时长（用户听得出）。

### 挖料清单（每项都能独立撑一页，全部有原文出处）

| 挖什么 | 原文在哪 | 撑起的页 | 典型页型 |
|---|---|---|---|
| 完整指标／变量表（十几到十八行） | 方法节的指标表 | 指标体系全表 | `info_full` + `table` 11.5 pt |
| 方法公式与逐步说明 | 2.3.1、2.3.2 这类小节 | 测度／分解方法一页 | `info_split` + `numbered` |
| 数据来源、代理变量、年鉴版次、缺失处理 | 数据来源小节 | 研究设计与数据 | `info_table_fig` |
| 概念演进或研究综述表 | 引言里的概念表 | 文献脉络与研究空白 | `info_split` 左表右文 |
| 逐年统计全表（基尼、Moran、得分） | 结果节的 Table 4、Table 5 | 差异结构 / 自相关十年 | `info_full` 表 + `highlight_rows` |
| 政策建议、分档措施 | 结论节 | 政策建议三档 | `info_three` |

先把这张表按原文“还没用过的表／节”过一遍再动笔；一页只挖一项，不把两项并成一页。

### 全表重算：扩页最值钱的部分

原稿常只引首末两个值，把整张表拉出来常能看到三件事，都值得单独一页或一段：

1. **中间有拐点**——总体基尼不是单调上升，而是某年见顶再回落；Moran's I 某年跳升、某年回落，能与政策节点、突发事件对上。
2. **分项涨幅差得很远**——区内基尼四个片区分别 +89%、+43%、+20%、−10%，其中一片是唯一收窄的；原表就有，只是原稿没算。
3. **贡献率结构变化**——主导项换人（区间 80%→69%、区内 12%→20%），比“总体在涨”有信息量得多。

从表里算比例时保留原文口径（分母取首年值），结论写成量级判断。自己算的页在讲稿里明说“**这页是我加的**，原文没有单独讨论”，页面不进结论条，也不写成原文结论。

### 扩页后的收尾

- 新页优先分给此前没用过的版式（大表 `info_full`、双表 `info_table_fig`、三档 `info_three`），但每次插入都要重查“同版式不连续超过 2 页”和 8 种下限。
- 页数变多后 `apply_notes.py` 会重算时长；讲稿必须按新页数补写，旧条目会直接被 `assert len(prs.slides) == len(SCRIPT)` 拦住。
- 备份上一版（`content.v15.bak.json`、`script_content.v15.bak.py`），交付说明里写清“上一版多少页、这一版多少页、新增页各自补哪一块”，用户据此判断值不值。
- 三栏页（政策三档这类）各栏要点条数写成一样多，否则短的那栏垂直居中，与邻栏错行。
