# 课程作业 / 课堂汇报：正文 ≥24 pt、每页 ≤6 行、指定字体

课程调研大作业、课堂汇报作业常给硬指标：正文不小于 24 pt、单页正文不超过 6 行、全稿黑体（或宋体）、封面带校徽。**这是验收指标，不是“没算过密度的期望值”**——用默认 20 pt 排完交上去会直接扣分。

开工前一次问清：页数或时长、署名（姓名 / 学号 / 班级 / 指导教师，没给就做成 `汇报人：＿＿＿＿` 的填空线）、是否需要 Word 讲稿。

## 一、字号档（`PPT_FONT_SIZES`）

```bash
export PPT_FONT_SIZES='{"para":24,"markers":24,"head":26,"note":20,"caption":17,"table":20,"cell":21,"summary":24,"lead":24,"small":14,"process":18,"label":20,"side":24,"foot":15,"pill":20,"check":24,"band":26,"region_band":22}'
```

正文 / 要点 / 引导句 / 结论条 / 小标题 / 栏首都 ≥24 pt。允许低于 24 的只有三类，交付时在回复里点名：**图注 17 pt、页码 15 pt、表格 20–21 pt**；参考文献页按 17–20 pt 排（正文 24 pt 时每条要 3–4 行，一栏放不下 3 条，会报“估计 2.05 in > 框高 1.62 in”）。**课程作业一般要求 10 篇左右**，按两栏 5+5、`info_split` + 两栏各 `valign: "spread"` 排：单条压成“作者 3 人 + 等 / et al. + 题名 + [J]. 刊名, 年, 卷(期): 页码”，全页统一 17 pt（同一页各条必须同号——`para` 的 `fit_size` 是逐条算的，只给高度不给字号会缩成一条一个大小，非常难看）；每条前置 `[1]`–`[10]` 连续编号并把编号写进 `strong`，深蓝加粗区分正文。两栏按条目长度配平（中文 5 篇 / 英文 5 篇各占一栏最省事），排完看渲染图：页码在连字符处断行（`183-` / `198.`）属正常排法，不要为它调列宽；某条只多出一个词时压短题名（“水驱后火驱油藏工程设计” → “水驱后火驱工程设计”）。**列进去的每一篇都要有引用落点**：正文没有它的位置时，在对应页的讲稿里补一句实测数据（“也门一个 14°API 的稠油油田做蒸汽驱方案优化，采收率从 52.2% 提到 57.3%”），不要出现“参考文献里躺着、全文没提过”的条目——老师会照着文献表翻正文。

**无文字层的 PDF 靠视觉读首页取条目信息**：`pymupdf` 读出来只剩几十个字（或首页为空）就是扫描件，不要猜作者与年卷期，也不要拿文件名当题名。用 `page.get_pixmap(dpi=150).save(...)` 渲成 PNG 丢给 `vision`，一次问清“题名 / 作者 / 期刊 / 年 / 卷(期) / 页码”，中文刊的首页一般带完整的引文行与 DOI；英文刊读首页眉（`Sci. Contrib. Oil Gas, Vol. 44. No. 3, December 2021: 183-198`）与标题块。同一篇里正文数据也可以用这个办法核对（摘要比正文页更好读）。

## 二、24 pt 下按栏宽给字数上限（全角字）

一页 = 1 张图 + 4–5 条一行要点，几乎不留长句。写完先按这张表量，别等 lint 一条条报孤行：

| 位置 | 净宽 | 一行字数 |
|---|---|---|
| `info_split` 单栏 | 6.35 in | 17–18 |
| `info_hero` main / side | 7.15 / 5.3 in | 20 / 15 |
| `info_big` main / side | 8.9 / 3.5 in | 25 / 9（侧栏只能放 4–6 字标签，放句子必折行）|
| `info_three` / `info_three_strip` 单栏 | 3.1–3.7 in | 9–11 |
| 表格单元格（21 pt） | 2.3 in / 3.6 in | 8 / 12 |

`info_big` 的 7 列侧栏在 24 pt 下只剩约 9 字/行，**不要用 `info_big` 放句子**——要放 4 条要点就换 `info_hero`（side 10 列）或 `info_split`。

## 三、稀疏页怎么填（不是加字号，也不是加套话）

- 文字栏的小标题与那句判断放**顶部 `region.band`**（`regions.<slot>.band = "…"`），不要用 `region.foot` 底部条：用户要的就是“小标题和矩形放上面”。band 吃 0.5 in，改完重建看 `over-full`；3.5 in 窄栏的 band 文字 ≤9 字。
- 总结 / 经验类页写成“两段 `section`（各 2–3 条要点）+ 一张中图”，三块并列时用 `info_mosaic`（左图 + 右上/右下两个 band 块）；三栏各一句的空心版式会被要求重排。
- 跨十几页统一改（如把全部 `foot` 换成 `band`）时，在内容脚本末尾用 `BANDS = {页标题: {槽位: 文字}}` 循环注入 `regions[槽位]['band']`，不要逐页改 JSON——漏一页就得重渲一次，而且改完看不出哪页没改到。
- 三栏页设 `"valign": "spread"`：栏首在上、要点散开，比默认居中更像刻意排版。
- `info_compare` 两栏设 `"valign": "top"`——默认 middle 会把小标题条压到栏中段，看着像出错。
- 三栏每栏只有 1 条要点时补第 2 条短要点（≤11 字），不要在栏里再起一层 `section`。
- 日志的 `has empty` 会一直报到 35%–50%：**24 pt 稿的稀疏是设计结果**，用户要的就是字大行少，不要为清零去缩字号或堆字；只处理真正难看的（小标题被挤、孤字、图太小）。

## 四、字体：全稿黑体（后处理，不改 `info_style.py`）

`info_style.py` 把拉丁写成 `Arial`、东亚写成 `微软雅黑`（共 721 处）。要求黑体时**不要改脚本源码**——会污染其他稿子；用 `scripts/set_font.py` 在 `dense_deck.py` 之后替换全部 XML 的 typeface：

```bash
$PY $S/scripts/set_font.py out/slides.pptx 黑体      # 默认同时把 Arial/Calibri 换掉，全稿只剩一种字体
$PY $S/scripts/set_font.py out/slides.pptx 黑体 --only 微软雅黑   # 只换中文，数字留 Arial
```

替换后自检：`{r.font.name for s in prs.slides for sh in s.shapes if sh.has_text_frame ...}` 应只有一个值。这一步会进 `build.sh`——重建会冲掉。渲染核对时 LibreOffice 会回退到系统中文黑体，看行不行以 PowerPoint 为准。

## 五、表格

4–5 列 × 5 数据行是 24 pt 稿的上限（6 行就顶到结论条）。列宽按内容给足：21 pt 下“井筒预处理”5 字要 1.85 in，“预热 320→163 d”要 3.6 in。宁可合成 2–3 列、把明细挪进讲稿，也别让单元格断词（`井筒预处⏎理`）。表头与正文同档字号。

**单元格 `highlights` 不要写带尖括号的子串**（`"< 1000"`、`"> 15"`）：渲染出来是 `•1000`，尖括号被吞成一个圆点，而同一张表里未高亮的 `< 1500` 正常显示——很容易只看到“有个红点”就漏过去。要高亮就选不带 `< >` 的值（`150–800`、`3–15`），或整张表不设高亮，把重点交给引导句。

## 六、页数与时长

- **15 分钟课堂汇报 ≈ 22–24 页**：每页 35–40 s，图页 20 s，关键结果 / 方案页 50–60 s。做到 26 页以上用户会直接回“控制在 22–23 面即可”——他要的是一条讲得完的故事，不是把材料摊开。
- 页数压不下来时按这个顺序合并，四处能省 5 页且不丢论证：① 蒸汽吞吐 + 蒸汽驱并成一页（本来就是接替关系）；② 指标预测 + 经济评价并成一页（一页讲“怎么算”和“怎么用”）；③ 设计示例的“指标预测”与“实施要求”并成一页；④ 删掉案例总览表（每个案例页自带判断句，总览只是索引）。删页后重排 `1.1、1.2…` 并跑 `spec_audit` 的编号连续性。
- 讲稿：中文朗读实测 **270–290 字/分**，15 分钟 ≈ 3600–4000 字，23 页按每页 150–170 字写（实测 23 页 3688 字 = 15.4 分钟）。写完用 `sum(len(s.notes…))` ÷ 275 自检，差 2 分钟以上就删字不删页；交付时说清估算口径，并指出哪两页可以带过。

## 七、内容骨架（“一个完整方案，自成体系”）

封面（校徽 + 题目 + 署名填空）→ 汇报安排 → **方法**：判别标准 → 设计流程 → 各类方案的设计要素（每种一页，参数表）→ 指标预测 → 经济评价 → **案例**：每案一页（条件 / 参数 / 效果；页数紧时总览表可省）→ 经验页 → **设计示例**：用文献里的真实对象参数 + 按文献技术界限定的设计参数，页面注明“取值依据” → 结论 → 主要参考文献 → 结束页。

设计示例是“自成体系”的关键：全部参数一张表 + 一句取值依据，指标曲线图注明“数值模拟预测，示意”，不把示意曲线说成矿场产量承诺。

## 七之二、页标题要学科化

用户会说“大标题还不够学术”“方向要再学术一点”。判断句留给引导句与结论条，标题只写学科通用表述，并把“某方法”补成“某方法的机理 / 设计要素 / 适用条件”：

| 太口语 / 太平 | 学科化之后 |
|---|---|
| 蒸汽吞吐设计要素 | 蒸汽吞吐与蒸汽驱设计 |
| SAGD 设计要素 / 火驱设计要素 | SAGD 的机理与设计要素 / 火烧油层的机理与设计要素 |
| 案例给出的设计经验 | 案例的设计经验与适用条件 |
| 3.1 设计示例：油藏与井网 | 示例：油藏条件与井网部署 |
| 产能与指标预测 | 指标预测与经济评价 |
| 结论 | 结论与认识 |

改标题时同步改 `BANDS` 里的小标题带与讲稿页首句，只改标题会让翻页时口播和页面各说一套。

## 八、校徽

学校的横版 lockup（校徽 + 中英文字标）从官网首页 HTML 里取 `images/...logo*.png`，多数是**白色透明底**：需要深色版时用 alpha 通道重着色（`Image.new(...,(10,44,92,255)); putalpha(a)`），不要用反色。325×75 px 用在页眉（高 0.5 in ≈ 185 dpi）够用，封面高 0.6–0.7 in 即可，不要放大到压标题。

封面被要求“再改改”时优先换 `"style": "panel"`：左 3.83 in 深蓝竖栏（`panel_title` 大字 + 0.02 in 细白线 + 三行 tagline），竖栏底部放**白色校名标识**（`add_picture` 到 y≈5.5、宽 2.8 in，上面再压一条 0.012 in 细白线），右侧 `kicker` + 两行题目（34 pt）+ 深蓝细线 + 署名三行。这样与目录页的深蓝左栏成一套；纯白居中封面中间那块空是补不掉的。
