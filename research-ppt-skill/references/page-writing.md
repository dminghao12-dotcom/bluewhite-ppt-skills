# 怎么写一页（JSON 写法、文献页标题、机构标识、组件）

> 本文件由原 SKILL.md 正文迁出（内容未删减），主文件只保留摘要与指针。

### 二、怎么写一页

**先从页型骨架起步**：按大纲里的页型编号，从 `assets/page-types.json` 取对应条目的 `skeleton`，给它加上 `"page_type": "P04"` 这样的编号（日志会按页型核对图的级别），然后只替换文字、图片和数量。下面是整份 JSON 的结构：

**文献怎么引进来（用户明确要求，别生硬）**：先从我们自己的卡点起头——「我们要测 X，卡在 A、B 两个麻烦上，于是找到这两篇」。每篇进来时先给一句它在桌上的理由（它答我们哪个问题），再给期刊、方法、样本、产出；两篇之间用「一篇答哪一半、另一篇答哪一半」串起来。文献卡页放论文首页裁片（`h` 给到 2.6 in 以上，别缩成 2 in 的缩略图）+ 期刊/方法/产出的短 `kv`，不要用大段摘要复述。

**述评的顺序是「背景 → 定位 → 框架」，不是一开篇就摆两张文献卡**：第 2 页先给研究背景的三层缺口（政策与产业 / 理论 / 测量），末尾落成三个研究问题；第 3 页才摆两篇文献的定位。用户原话：「第二面不是应该先引入背景吗，不然谁知道这两个在干什么、回答了什么问题」。

**页标题用学科通用表述，不用文学化短语**：研究背景、两篇文献的定位、研究框架、研究设计与数据、指标体系、维度识别、信效度检验、效标效度、构念辨析、量表开发路径。`从吸引子到地方感` 这类要改成 `研究框架`（用户原话：「最上方的大标题应该纯官方而不是通俗」）。判断句留给导引句与结论条，不进标题。

**文献汇报的页标题走章回体：`一、研究背景` / `二、研究意义` / `三、研究框架` / `四、材料与方法` / `五、结果分析（药效）` … / `六、讨论` / `七、结论`**。用户否掉了 `1.1 肺纤维化与 NETs` 这类“带主题的编号标题”，原话是「大标题要学术一点，比如研究背景、研究意义，这样来展开」；结果部分共用同一个章节名，用括号小注分页（`五、结果分析（炎症）`、`五、结果分析（靶点）`），不要每页自取一个主题。换成中文序号后 `spec_audit` 的编号检查会打印 `编号：[]` 并跳过，不需要为了它改回 `1.1`。

**小标题写判断句，分点比它小一号**：`section.head` 写这一栏的结论（`临床基础充分`、`三个问题待答`、`三点解释成立`、`三处证据缺口`），不要写标签式名词（`已有基础`、`仍缺的部分`）；`head` 23 pt、`items` / `markers` 19 pt，相差一级就够。用户原话：「小标题给一个精炼的总结然后开始分点讲重要的点（分点的内容可以小一号字）」。

**文献汇报的页标题按中文序号 + 章节名走，不写「1.1 肺纤维化与 NETs」这种话题式标题**（用户原话「大标题要学术一点，比如研究背景，研究意义」）：`一、研究背景` → `二、研究意义` → `三、研究框架` → `四、材料与方法` → `五、结果分析（药效）`…（结果占多页时统一写「五、结果分析（子题）」，括号里 2–3 字）→ `六、讨论` → `七、结论`。**小节标题同样先给一句判断再分点**：`section.head` 写可读的结论（`临床基础充分` / `三个问题待答` / `三点解释成立` / `三处证据缺口` / `三项后续工作`），下面 ■ 逐条给证据，不要拿「已有基础」「本研究的问题」这类目录式标签当小标题。

**小节标题与分点要差一档字号**：文献汇报用 `head 23 / para·markers 19`（用户原话「分点的内容可以小一号字」），小标题因此能承载判断句而不被正文压住；这个档位与默认 20 pt 档（22 / 20）的差别只在两处，改 `PPT_FONT_SIZES` 的两个键就够，不要顺手动 note / table。

**论文原图必须进稿并单独解读**（用户会直接问「怎么没看到对论文重要图的解释」）：方法/框架图至少各占一页，标「原文 Fig. N」，用 PDF 内嵌图原样导出（`page.get_images` + `Pixmap`），不重绘、不裁切；宽图（≥3:1）用 `info_focus` 给到 12 in 宽，其余用 `info_big` 给到 8.5 in；图注写「怎么读」，页内写「看到什么 / 说明什么」。案例地照片、量表结构图同理。

**述评的语言用学术语体，不是口播稿**（同一轮用户要求「语言应该尽可能学术化、去 AI 化」）：页面用名词化表述（研究缺口、构念操作化、信效度检验、极差标准化），讲稿也写成完整书面句。避免口语词汇与口播句式：「卡在」「说白了」「站不住」「坑」「伙伴」不要用，也不要「一者……一者……」的排比收尾。对照：`这次我讲两篇文献` → `本次汇报以文献述评的形式展开`；`它答的是我们哪个问题` → `该研究回应的是内涵界定问题`。术语照用，只把语气降下来，不把内容简化。

**专业术语直接使用（同一轮用户要求）**：随机游走、构念效度、AVE、CR、主客互动、情感补偿这类术语照写，不为了「好懂」换成大白话；首次出现给一句解释就够（「AVE，平均方差抽取量，看收敛效度」）。术语被稀释成口语，听众反而不知道你说的是哪个指标。

**文献汇报的配图分工**：概念链、机制、情境类图（吸引子→互动→感受、城市关系缺口→乡村补偿）交网页端 GPT 生成，一图一事、每张独立画布；定量结果（各城得分、路径系数、方差解释率）仍由本机 matplotlib 按原文数值重绘。GPT 图的图注要写明「按原文构念整理，示意」，不冒充论文原图。

页型是起点，不是铁律：默认版式把图挤到 2.4–2.6 in、标签读不出来时，换同类别更宽的版式——P05 换 `info_four`、P12 结论换 `info_three`、P13 换 `info_compare`——并在交付说明里写明换了哪几页、为什么。骨架里的图位数量只是默认值，换版式后按实际格子重排。

```json
 "slides": [
  {"type": "cover", "title": "…题目…", "subtitle": "…", "info": ["汇报人：…", "指导教师：…", "2026 年 10 月"]},
  {"type": "agenda", "items": ["研究背景与问题", "方法与技术路线", "结果与应用", "计划与结论"], "active": 0},
  {"title": "2.1 两种预测方案对比", "layout": "info_split_strip",
   "lead": {"text": "对比两种方案的思路、优点与局限，说明各自的适用条件", "highlights": ["适用条件"]},
   "regions": {
     "left":  {"band": "方案 A：点预测", "items": [
        {"type": "row", "widths": [1, 1.15], "items": [
           {"type": "section", "head": "方法思路", "items": ["历史负荷 + 气象输入", "输出单一预测值"]},
           {"type": "figure", "file": "images/a.png", "caption": ""}]},
        {"type": "row", "items": [{"type": "section", "head": "优点", "items": ["结构简单"]},
                                  {"type": "section", "head": "局限", "items": ["不给误差范围"]}]}]},
     "right": {"band": "方案 B：区间预测（本文）", "items": ["…同上…"]},
     "bottom": {"side": "适用场景\n与选择建议", "side_w": 1.9, "items": ["…"]}},
   "summary": {"text": "选择依据：调度对风险敏感时，用区间预测替代点预测", "highlights": ["用区间预测替代点预测"]},
   "notes": "这页比较两种方案……"},
  {"type": "end"}]}
```
- 机构标识：厦大能源学院写 `"brand": "xmu"`；其他单位写 `"header_logo": "logo.png"`（横版，页眉用）和 `"logo"`（方形）；都没有就写 `"institution": "单位 / 课题组"`。用户给一张“圆标 + 中英文字标”的横版 lockup 时，同一文件同时填 `header_logo` 与 `logo`，不要自己拆成两半或改色：
  - 页眉按高 0.5 in、右缘对齐 13.02 in 放置（页标题框到 10.1 in，不会撞）；横版 3.5:1 的 logo 此时约 1.76 in 宽，只有校徽图形能认出来，字标偏小是正常尺度，不要为了“看清校名”把它放大到压标题。
  - **`paper_cover.py` 重建第 1 页会把封面 logo 一起冲掉**：`build.sh` 里必须在 `paper_cover.py` 之后接 `scripts/add_cover_logo.py out/slides.pptx images/logo.png`（形状命名 `机构标识`，右缘 13.02、高 0.42、top 0.13）。
  - 封面 logo 的纵向位置要避让标题：放在 y=0.42、高 0.56 时，居中标题的末字会被校徽压住（标题框 9.5 in 宽、中心约 8.6 in，长题会伸到 11 in 以外）。上移到 y=0.13、高 0.42 即不再压字；改完看渲染图确认。
  - `spec_audit.py` 已跳过名为 `机构标识` / `单位标识` 的形状，页眉 logo 不会再被当成内容图报“图片只有 1.8×0.5 in（<2.6）”；自绘脚本里给 logo 的 shape 也要沿用这两个名字。
  - 多个原始标识并排时，先按等比尺寸计算标识组最左缘，再将实际页标题框右缘收至该位置之前；只缩短标题文字却保留伸入Logo区的宽文本框，仍会产生重叠告警。把全部标识放在最后的后处理步骤，逐页机检数量，封面和结束页也计入。封面姓名从原图放大核对，不能用规划模型转录结果替代原图。
- 页面骨架：`title` → `lead`（可加 `tag`）→ 可选 `sublead` / `band`（可带 `images` 衬底）/ `process` → `layout` + `regions` → `summary`。
- 区域常用：`band`（+`num`）、`head`（+`num`、`head_style: bar`）、`side`、`foot`、`fill: dashed / light / none`、`grid: [列, 列数, 行, 行数]` 自由拼版。
- 封面 `"style": "panel"` 是左侧深蓝竖栏版；结束页写 `points` 是“回到本次汇报的核心”版。
- 用户的简洁首尾偏好：封面主标题、副标题默认各占一行，不主动加入换行；检查PDF实际渲染行数，不能只验证源字符串没有`\n`。“汇报安排”页只留页标题和编号安排，内容JSON不写`lead`、`band`、`summary`，不要给这些字段塞空说明。用户本次另有要求时优先。
- 组件常用：`section`（小标题条 + ■ 要点，最常用）、`figure`（`caption_style: box`、`overlay`）、`markers`、`note`、`para`、`chevrons`、`label_rows`、`links`、`stages`、`matrix`、`timeline`、`cycle`、`process`、`rows`、`fig_list`、`card`、`table`、`quadrant`、`callout`、`kv`（信息条）、`numbered`（编号议程）、`branch`（问题拆解树），以及原生 `chart` / `formula`。参数与样子见 [info-style.md](info-style.md)。
