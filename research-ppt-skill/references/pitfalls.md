# 踩坑清单（前几轮真实踩过的）

> 本文件由原 SKILL.md 正文迁出（内容未删减），主文件只保留摘要与指针。

### 五、踩坑清单（前几轮真实踩过的）

| 坑 | 正确做法 |
|---|---|
| 用生成脚本末尾追加的一段“收尾处理”（给每页补 `foot`、改某几页标题、统一居中）改稿，跑完 exit 0、日志也无报错，但渲染出来一点没变 | 那段代码排在 `json.dump(...)` **之后**了：`SLIDES` 写完以后才被改，磁盘上的 `content.json` 还是旧的。所有对 `SLIDES` 的二次加工都必须写在 `CONTENT = {...}` 与 `json.dump` 之前；改完用 `grep 关键词 content.json` 或看渲染图确认真的落地 |
| 用了 `section` 章节页眉 + `header_logo` 的稿子，lint 几乎每页报“页标题 与 机构标识 重叠 0.96 in²” | 名义重叠：`headline()` 把页标题框一直画到 12.9 in，而 logo 左缘在 10.98 in，两者框相交但文字离得很远。抽两三页看渲染图确认没有真撞上就保留，交付说明里写一句；不要在 14 字以内的标题上再压字，也不要为了清零把 logo 挪出 13.02 in 的右缘对齐 |
| 留白多就把字号调大 | 用户明确否定。补具体的图、小标题要点、流程条，或换更紧凑的版式 |
| 页面/讲稿有 AI 味：“不是 A 而是 B”“一条…一条…”、口号式断句、段尾升华 | 按 [speaker-notes.md](speaker-notes.md)「去 AI 味」改：补主语、给数字、停在事实上；页面短句和备注都要过 |
| 论文或补充材料原图的图号、时段、单位与正文自相矛盾，仍原样贴进页 | 逐张把图内标签对回正文再贴：实测一张双节点示意图，图内标题写的是另一张图的编号、末端又写“10 h/night”，而正文与 SI 正文都按 22:00–07:00 九条记录统计。这种图不入稿——用原生组件（`section` + `formula` + 参数表）写正文的正确口径，交付说明里点明源图自相矛盾之处；原始论文文件一个字都不改，修正只做在自己的副本上 |
| 窄栏自动折行，第二行只剩一两个字（孤行） | 缩短到一行，或在语义边界写 `\n`；lint 会报，看图确认 |
| 一页红字堆了五六处 | 只留这页最该记住的；其余改黑色加粗（`strong`） |
| 高亮词写错一个字就静默失效 | 照抄正文子串；看生成日志里的“高亮词不在正文里” |
| 目录标题变大后被行高压扁、或三行挤在一起 | `numbered` 的标题字号走 `size`；三项目录用 28 pt，行数为 4 以上回到 20 pt，序号方块与说明字号不动 |
| 把 ■ 换成 ✓ 后符号挂在标题左缘外面、并与首字粘连 | ✓ 的左缘与上一行小标题文字左缘齐平（textbox 左边界 = 标题文字左边界），✓ 与文字之间插一个窄空格；放大渲染图核对 |
| 并列三条里只给一条加深蓝竖条“表示重点” | 并列关系会被读成第三条特殊；重点交给右侧聚焦块、标题加粗或总结条，三行结构与分隔线保持一致 |
| 页面上出现任何竖条：`section` 的 `head_style: "bar"`、`callout` 的左侧红竖条 | 这个用户不接受任何竖条。小标题用默认 `fill`（浅蓝条 + 深蓝粗字）；强调一律改成正文里的红字加粗（`highlights`），既不用竖条也不用红框块（见「强调只用红色加粗文字，不用红色框块」）。被要求去掉竖条时按组件清单全稿搜 `head_style`、`callout`、`side_tag`，改完重渲逐页看——只改一处，下一轮还会被同一句话打回 |
| 表格单独一页，下面空半页或行高被拉得很稀 | 表格 + 图带（`grid` 分上下）或表格 + 侧图（`info_table_fig`） |
| 表格单元格 `highlights` 写 `"< 1000"` / `"> 15"`，渲染出来变成 `•1000` / `•15`（同一张表里未高亮的 `< 1500` 却正常） | 高亮串里的 `<` `>` 会被文本处理吞成一个圆点。高亮只选不带尖括号的子串（`150–800`、`3–15`），或整张表不设 `highlights`、把重点交给引导句；改完必须看渲染图确认单元格文字没坏 |
| 表格 `highlights` 写成按单元格的二维列表（`[["2.6"],["37.70"]]`），`dense_deck.py` 当场抛 `TypeError: decoding to str: need a bytes-like object, list found`（`re.escape` 收到了 list） | `table.highlights` 只认**一维字符串列表**，其中出现的串在所有单元格里自动标红；要挑某一格就让该格的串唯一（`37.70` 这种只在目标格出现），不要套二维 |
| 流程条、深蓝标签塞进 1 行高的格子被挤 | 给它至少 2 行网格高度；日志 `over-full` 会标页码 |
| 想给某个分区加一条深蓝栏首，写成 `{"type": "band", "text": …}` 放进 `items` | `band` 是 **region 的键**，不是组件类型（`_markers_paras` / `stack` 都不认识它）：写 `regions.<slot>.band = "…"`。放进 `items` 里那一块根本不渲染，日志也不报错，只表现为“这页少了一条标题带”，很容易误判成尺寸问题 |
| 象限、说明块只写四五个字，框里大片空 | 每格写“标题 + 两行说明” |
| 图片衬底标题带用了花哨的图，字看不清 | 用照片或简单图，衬底默认 80% 深蓝遮罩 |
| 长页标题撞到右上 logo | 页标题 ≤ 14 字，判断放进标题带 |
| 改内容 JSON 用字符串替换，0 命中但脚本照样 exit 0 | 按结构改：`json.load` → 按页标题定位 → 改 dict → `json.dump(ensure_ascii=False, indent=1)`；改完看产物，不只看命令成功 |
| 删页 / 合并后小节编号断号、目录项数不对 | 重排 `1.1、1.2…`；目录出现次数 = 部分数（lint 查断号） |
| 页码写死，删页后全错 | 需要页码时开 `meta.info_footer`（用幻灯片编号字段） |
| GPT 图片标题与页内标题重复 | 生图时不加大标题；旧素材仅去除主体之外的独立标题条，不按固定百分比裁切 |
| 中文断行和标点在 PowerPoint 里乱 | 脚本已给每个 run 写 `lang="zh-CN"`；手工加的文本框也要带 |
| LibreOffice 预览和 PowerPoint 断行不一样 | 字体不同；终稿用 PowerPoint 打开检查一遍 |
| WPS / PowerPoint 打开后自动重存，改坏了交付件 | 交付件从生成的原件拷贝，比对 md5 |
| 图片找不到、提示词文件不知道去哪了 | `file` 相对**内容 JSON 所在目录**；提示词导出到 PPTX 输出目录的 `images/` |
| `highlight_rows: [0]` 把红框画到了表头，或 `[3]` 框到了第 3 行而不是第 4 行 | 从 1 数正文行（不含表头）：第 1 行正文写 1；生成后看渲染图确认红框落在目标行 |
| 箭头流程条每块字太多，被缩得很小或折行 | 每块 ≤ 6 字；日志会提示该缩到几个字 |
| 8 页短稿的表格塞进 `info_table_fig` 左槽（13 列 ≈ 6.9 in），“通胀与菲利普斯曲线”这类九字章名被拆行，六行全报孤行 | 三列按 2.25 / 2.0 / 2.45 in 分，正文压到 ≤12 字（“短期取舍、预期”），章名一列单独留够 2.25 in；还放不下就换回 `info_full` 通栏表，但那样全稿只剩 5 种版式、短稿的 6 种上限就达不到，得同时换另一页的版式 |
| `info_compare` 两栏要点条数不等，两张图被压成一大一小（实测 5.43×3.61 vs 4.80×3.19） | 两栏小节数与每节要点数保持一致，图才等高；多出的那条挪到讲稿或结论条 |
| 时间轴页用 `info_full`，轴下方留 1.2–1.5 in 空白，lint 报“留白” | 改 `info_focus` + `grid` 覆盖（main 0–8 行、bottom 8–4 行），底部放 `kv`（教材 / 学会）+ 一条 `note`，比硬塞第三条要点自然 |
| 人物页要真实肖像，又不想破坏蓝白风 | 用诺奖官方插画版肖像（得主页 `og:image`，白底线稿）；`figure` 给 `h: 3.7` 竖排，旁边 `section` 只排 4 条履历——第 5 条会把最后一行顶成“研究员”孤行 |
| GPT 生图与页面主题贴错（把「情感补偿」图画到了「吸引力链路」页；同批两张变体都是 1672×941，缩略图上分辨不出） | 落盘按内容命名（`gpt-attraction` / `gpt-emotion`），不看 blob 序号；贴页前把每张图单独打开核一次主题，图上出现的关键标签（城市生活 / 乡村目的地）就是判据；同一图位常出多张同题变体，全部取回再挑 |
| 一个说明框里写了一长句，含三四层意思 | 拆成 ■ 要点；日志“一句话说不清”会提示 |
| 框架图 / 核心结果图和别的内容挤在半栏，缩成小图 | 标 `role: "big"`，用 `info_big`，去掉标题带；日志会报大图尺寸不足 |
| GPT 给的大纲只有标题和要点，拿到后不知道怎么编排 | 用 outline.md 的提示词并附 page-types.jpg，让 GPT 逐页写页型编号和大 / 中 / 小图位 |
| 参数不知道怎么写 | 先查 [info-style.md](info-style.md)「参数速查」，再看两份示例 JSON，不用读脚本 |
| 带图例、带刻度、带注释的完整图缩进三栏或 4 in 格子，字小到投不出来 | 给窄格子单独出一版“简化图”：去掉图例与刻度，只留 2–3 个大字标签和粗线；完整版留给大图页或图带 |
| `stages` / `rows` 不带图时，要点被顶到框底、上半空白 | 每个阶段配一张只表形态的小图；**纯文字的三阶段框架不要用 `stages`**，改用 `info_three` 三栏（band + section + note），否则加多少条都沉在框底。**`info_full` 里放四段 `stages` 一样沉底**（框高固定，标题与要点都贴在框的下半、上面空一块）：四步内容页（每步 3–4 条要点 + 一个产出）直接用 `info_four`——`band` 写步骤名、4 条 `markers`、`note` 写产出，一版就过审计 |
| `branch` 里一句长说明会在框内垂直居中、上下飘 | 卡点页改用 `info_compare`：左侧卡点（现象/影响/已尝试）+ 中间箭头 + 右侧三个原因，每格两句 |
| `info_four` 四栏页各栏要点换行数不同，栏首小标题高低不齐、底部说明块也错开（用户直接说“这页好歹对齐一下”） | 栏内条目逐栏对齐：同条数，每条控制在栏宽一行内（6 列约 3.1 in，18 pt 约 9 字）；仍不齐就改 `info_big`，把四栏内容画成一张讲递进关系的大图（如四层创新画成阶梯图），对齐问题自动消失 |
| 纯文字栏页改了几轮还是“一排文本框”，用户仍说“图丰富一点” | 不是往里塞图标，而是整页换成**一张讲同一件事的大图**：判断依据错配、四层递进、阶段路线各一张，侧栏只留 3–4 行短说明；`timeline` 页也可用四阶段路线图替掉，原生 timeline 只留给时间跨度必须精确的研究计划 |
| 版式不够 8 种：`info_full` 一页页地用 | 数一遍 `layout`，把天然适合 `info_focus`（大块 + 底部条）、`info_compare`（左右对照）、`info_rows3` 的页换过去 |
| 本机 matplotlib 画的示意图，曲线或柱子跑到画布外面 | 先设 `xlim/ylim` 再画，或给坐标留边距；生成后必须看一眼缩略图，别只看 exit 0。**要强调某一根柱子时改柱色（`#DE1515`），不要在它上面叠一个红色数值标注**——标注会压住柱体或邻柱的标签（实测“58%”横跨到隔壁分组，图上像坏了一块）；标签只保留柱尾那一个百分数，`if value == min: color=RED` 一行就够 |
| 多标签插画塞进 2.2–2.6 in 的格子，投影时字糊成一团 | 要读的标签 ≥ 3 个的图，宽度给到 3.5 in 以上：换 `info_three` / `info_four` 让图占整栏，别把图缩小了事；`spec_audit` 现对三／四栏页的图直接卡 ≥3.5 in |
| 版面挤不下时把图缩小“凑进去”（图 + 小标题条 + 结论条三样都要，就把图从 3.9 in 压到 3.4 in） | 先改版面、后动图：删掉那条重复的小标题条（栏首只保留一层）、把说明挪进图注或结论条、必要时换 `info_three` 占整栏。skill 明写“看不清的小图宁可删掉，也不缩着放”，缩图是最差的一档 |
| 生图带大片白边就原样贴进图位，正文上方空一大块 | 贴前先裁白边：PIL 取非白 bbox（阈值 sum<735）＋约 1.2% 内边距，再按新比例重算图位；实测同一图位裁边后从 5.8 in 增到 8.3 in 宽、标签才看得清。裁边不算“裁切主体”，但不得切到标签、箭头与图例 |
| GPT 插画放进 `rows` 行（图被限到 2.4 in）后变成邮票 | 行式版式只配“一图一事、零文字”的图；要放有标签的插画就换三栏 |
| 取网页图字节时 `String.fromCharCode.apply` 直接爆栈（1 MB 图、600k 分块） | 分块降到 8192 字节；base64 再用 700k 切片分次取回，一次返回整串会拿到 `{}` |
| 用 `js(expr, target_id=tid)` 读页面、再用 `cdp("Input.insertText", text=…)` 写输入框，结果整段需求打进了**另一个会话**的草稿（`js` 按 target 生效，输入事件走 harness 的当前活动页） | `switch_tab(activate=True)` 返回成功也不等于活动页已切换。固定写法：`sid = cdp('Target.attachToTarget', targetId=tid, flatten=True)['sessionId']` → `cdp("Input.insertText", session_id=sid, text=msg)` 写文本 → `js("…发送按钮.click()", target_id=tid)` 点发送 → 发送前用 `js(…, target_id=tid)` 读回 composer 头尾各 20 字核对。发现打错了标签页，先用 selectAll + delete 清空那个草稿再切走，别发出去 |
| `numbered` 与一张图并排（外层 `row` 给 1.4:1）时，标题列按默认 `title_w` 只剩约 2.4 in，10 字标题折成两行、右侧说明跟着错位、行高不齐 | 给 `numbered` 显式写 `title_w: 0.4–0.45` 与 `text_size: 15–16`，标题压到 ≤7 字（“1950 年代”“急救核心”“昏迷的早期识别”）；时代 / 序号放 `title`、判断句放 `text`，两者别互换 |
| 一栏塞四块（诊断 `note` + 目标 `kv` + 措施 `section` 4 条 + 评价 `note`）报 over-full，改成 `info_stack` 又报 0.39 in | 4 条措施的 `section` 单独就占约 2.8 in，加评价必然溢出。评价挪进页面 `summary` 条（它本来就是“落脚点”），栏内只留诊断、目标与措施；或换 `info_hero_left` 让正文拿到 14 列宽 |
| `info_compare` / `info_three` 每栏只有 2–3 条要点，框里空掉 40%–50% | 分区的小标题与那句判断一律放**顶部**：`regions.<slot>.band = "…"`，**不要用 `region.foot` 的底部深蓝条**——用户明确要求“把小标题和矩形放到上面而不是下面”，底条读起来像页脚，还和引导句/结论条重复。band 会把内容整体下移约 0.5 in，改完重建看 `over-full`；窄栏（3.5 in）band 文字压到 ≤9 字，否则 lint 报“标题带文字溢出”。补完仍空就换更宽的版式，不要靠加套话 |
| 封面用 panel 版，左竖栏 tagline 下面空出一大块 | `_cover_panel` 支持 `figure` 槽（`[0.5, 4.0, 2.83, 2.3]`，`fit: cover`），放一张与主题直接相关的实物图（药品、设备、样机）；封面的第一视觉由此有内容，不必再加文字。**课程 / 学术稿更适合在竖栏底部放白色校名标识**（官网 lockup 多自带白色透明版，`add_picture` 到 y≈5.5、宽 2.8 in，上方再压一条 0.012 in 细白线）：`figure` 槽塞示意图会被 `fit: cover` 裁成看不懂的一块，而校名标识天然是“左下角一块”，正好补掉竖栏下半部的空白。纯白居中版封面被用户判“单薄、中间一大块空”时，直接换 panel 版——它与目录页的深蓝左栏自然成一套 |
| 用户说“字体大一点点”，把 `PPT_FONT_SIZES` 整体 +1 档后一批页报 over-full | 先按页裁条目（4 条压到 3 条、长句断成两句）、必要时把某几页换更宽的版式；**不要把字号退回原值**——用户要的就是更大。`para` +1、`head` +2 的幅度（20→21 / 22→24）视觉上刚好“大一点点”，一次到位，别分两轮加 |
