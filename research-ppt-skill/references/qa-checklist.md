# 交付前自检（全文）

> 本文件由原 SKILL.md 正文迁出（内容未删减），主文件只保留摘要与指针。

### 六、交付前自检

- lint 0 错误；生成日志无 `over-full`；渲染图逐页看过（留白、孤行、图是否够大、红字落点）。
- **按 skill 逐项验收，不以自动检查代替**：文献大图是否尽量完整、是否有整篇研究框架、缺框架是否已按要求AI生图、页面与讲稿是否逐句去套话。核对实际 PPTX/PDF 和来源图，发现偏离就说明并改正，不能只凭 lint 或网页端“可交付”声称完全符合 skill。
- **大图尺寸核对实际图片，不只看图位框**：`role: big` 的告警只检查外框，双行盒式图注会占掉高度，导致图片实际不足 7.5 in 宽 / 4 in 高而日志仍通过。交付前用 python-pptx 读图片 shape 的 width/height；不达标就压缩为单行图注或减少重复文字，重渲并再量实际图片尺寸。
- 每页：一句话判断清楚；说不清的都已分点；大图够大、小图不承载细节；没有大块空白；红字 ≤ 4。
- **结果图页逐页点一遍三段解读**：`怎么读 / 看到什么 / 说明什么` 三段都在，数字与原文对得上，子图号（`A–C rCCL3 回补、D/E 共定位`）写进解读里，不让听众自己在图上找。文献汇报里漏掉解读的图页是最常见的打回理由。
- **空间适配看主体，不只看框或图片尺寸**：检查图片长宽比、内部留白、实际主体占比、标签可读性；宽格中出现窄竖图或小邮票即不合格。小图优先去掉内嵌图注，说明用原生文本单独排，避免图注重复预留高度把主体挤小。lint 0警告不能代替这一项视觉验收。
- **全稿先去重复逻辑再排版**：同一证据链、同一评价指标、同一结论不要换个页型反复讲；用户指定页数时包含首尾页，以删并冗余为主，不把更多内容硬塞小。
- **小标题去重可机检**：读 PPTX 里名为「小标题」的形状，同一页的文本集合去重后数量应等于分区数；有重复就说明 `region.head` 与 `section.head` 各写了一次。并列栏要居中时用 `section(head_align: "center")`，并在机检里确认 `paragraph.alignment == 2`。
- 全稿：20页级汇报至少8种版式，短稿不为凑版式增加页数；同版式不连续超过2页；长稿分节目录与部分对应，简短稿可只留一页编号安排；编号连续，相邻页不重复用图。
- 改页后同步重写备注并重导Word讲稿，检查“左图/右图/四步/本页表格”等指向，不能直接拼接被合并页面的旧备注；具体核对见 [speaker-notes.md](speaker-notes.md)。**合并页（两页并一页）的讲稿按新页的分块顺序重写成一段**，字数取合并前两段之和的 70–80%；粘起来的两段会在一个“然后”上露馅，而且听众会在同一页听到两次“这一页”。
- **语言去 AI 味**：页面短句和 `notes` 都按 [speaker-notes.md](speaker-notes.md)「去 AI 味」过一遍；重点查负向并列、三项排比、口号式断句、段尾升华。不能只改讲稿，页面标题和结论条也要改。
- **自动检查只作结构门槛，不能当验收**。`lint` 与 `spec_audit` 全绿只说明可机检项过了；它们**看不到**四件事：栏首有没有真的居中（`region.head` 那种左右错位）、图内标签在投影尺寸下能不能读、图四周白边有没有吃掉主体、主体在格子里占多大比例。这四类必须逐页看渲染图判断——把工具绿灯当成“符合 skill”，正是被打回“你为什么不按它做”的原因。
- **每份新稿开工前，先重读本文件的「图的分级」「小标题去重与对齐」「述评的语言用学术语体」三节**：这三节是最容易凭印象写错、又最容易被用户逐条挑出的硬规则，读一遍比返工便宜。
- 图：需要读标签的插画都 ≥ 3.5 in 宽；没有把带标题条的 GPT 插画直接贴进去；定量图都标了“示意数据”。
- 默认只交PDF、PPTX、Word演讲稿三个单独文件；PDF同时作为预览。不默认交付ZIP、总览图、说明文档、审核报告、原始材料或数据源码。内部检查和渲染仍须完成，缺的真实素材在对话里简要列清。
