# 出空白模板、内嵌视频、风格库与配色档位

> 本文件由原 SKILL.md 正文迁出（内容未删减），主文件只保留摘要与指针。

### 六点五、出空白模板（页型样张）

用户要“我的 PPT 模板”“蓝白风格的模板文件”时，出一份 20 页上下的样张：封面 → 目录 → 用法页 → 页型索引（一页 8 行表，16 类拆两页）→ 每类页型一页（`assets/page-types.json` 的 `skeleton` 当结构底稿）→ 结束页。

- **文字换成可替换的占位说明**，不是示例数据：`页标题 Pxx …`、`一句话说明`、`一条发现，带数字`。样张里出现具体数字会被当成编数据；“参见材料 A”这类元话语又会踩内容红线。
- **图位只写 `label`，不写 `file`**：占位框会显示“预留图位 + label”，把建议尺寸写进 label（`中图 · 约 6×3.4 in`、`大图 · 宽 ≥7.5 in（一页只放这一张）`），图位本身就是使用说明。lint 的 9 条 `仍有预留图位` 提示是预期结果，不要清零。
- **`spec_audit` 的两个硬卡点**：① 版式连排超过 2 页；16 类是顺序排下来的，`info_full` 会连出 4–8 页 → 把流程页/时间轴页换 `info_focus`、表格页换 `info_table_fig`、卡点页换 `info_compare`（顺带也是推荐版式）；② 图片按 2.6 in 下限检查、**不看 `role: small`** → 四角小图标（1.8 in）会被判失败，闭环/四角页干脆去掉图标，用 `markers` + 中心 `cycle` 承担图形。
- **表格塞进 13 列的半栏**（`info_table_fig` 左槽）时列宽只有 2 in 出头：4 列必断词、出孤行。合成 3 列、每格 ≤6 字，字号 16 pt 仍可读。
- **三栏栏首标题要居中**：`region.head` 不读 `head_align`，改成 `{"type": "section", "head": "结论一", "head_align": "center", "items": []}` 放在栏首，再排图和 `markers`。
- **交付件**：PPTX + PDF + 总览 PNG + 使用说明 docx + 每页备注 docx。`notes_docx.py` 的标题写死“讲稿 · 共 N 页 · 预计 X 分钟”，模板用它导出时先用 python-docx 把第二段改成“每页备注 · 共 N 页 · 这一页型怎么用”，否则文件看起来像演讲稿。
- 使用说明里必须写清一条限制：这是“页的集合”，不是 PowerPoint 母版版式，增页靠复制幻灯片，不靠“新建幻灯片 → 选版式”。用户以为能选版式会失望。

### 七、内嵌视频（录屏页）


需要真内嵌 mp4 时用 `scripts/embed_video.py`（细节见 [embedded-video.md](embedded-video.md)）：媒体部件名用 ASCII，整份 < 25 MB（先用 ffmpeg 压），另交一份独立 mp4 作后备。

### 风格库与扩展（当前只有一种）

**配色档位与风格是两件事**：配色由 `scripts/theme.py` 的 `THEMES` + 环境变量 `PPT_THEME` 切换（`blue` 默认、`purple`、`green` 生命绿、`inkgreen` 墨绿 `#17493A`（医院 / 单位墨绿 VI，章节带压到 `#0E3226`）、`jnu` 江南大学蓝 `#0A418D`、`bank` 金融蓝、`academic` 学术蓝 `#183A6A`、`warm` 暖橙 `#B24A1E`（会议 / 公益 / 关怀类选题，章节带 `#8C3112`、浅底 `#FBEDE1`、强调 `#B3261E`）），`meta.style` 只管版式体系。每档主题还带一个 `head` 键（章节带色，默认 `#92071C` 深红；`academic` 档与主色同色，页眉整条深藏蓝）。用户给校色 / VI 时**加一档 THEMES，不要手改 `info_style.py` 里的色号**：

- 主色取校色但**压暗到能读**——亮绿 `#00D200`、荧光蓝这类直接做标题和正文会看不清：标题 / 色块 / ■ 用深色版（生命绿取 `#127A3E`），底纹取浅色版（`#E8F7EC`），与校徽仍属同色系。
- `build.sh` 里必须先 `export PPT_THEME=green` 再跑 **所有** 脚本：`prep_figs` / `dense_deck` / **`paper_cover`** 都要同一个变量，否则封面竖栏还是蓝的、内页已经是绿的。
- **用户给一份现成 PPT 说“参考这个蓝主题”时，色号从渲图里取，不要凭肉眼估**：`soffice --convert-to pdf` → pymupdf 逐页 `get_pixmap(dpi=90)` → PIL 裁页眉条 / 主导色块 / 页底条，用 `collections.Counter(...).most_common(6)` 读实际色号（实测参考稿是深蓝 `#064090` 页眉渐变加蓝绿 `#1475A2` 主调，肉眼会误判成单一藏蓝）。一组主色通常含两档：深色给标题带与色块、中间调给编号/图标/次级条，五级 `layer` 按深→浅过渡。加成一档 THEME（`bank` 就是按这个办法从竞赛稿里取的；`academic` 也是——实测那套“学术蓝”是主色 `#183A6A` + 蓝灰 `#647B9B` + 浅底 `#E8EDF4`），然后 `PPT_THEME=<名称>` 跑全部脚本。**取色时先按饱和度过滤再统计**（`a.max(1)-a.min(1)>25` 且排除白/黑），一次就能同时拿到主色、副色与浅底三档，比逐块裁切快；**在正文页上取样，不要用封面**——封面常带照片和渐变，直方图会被带偏。换主题时 `head` 键要一起改，否则章节带还是上一套的颜色。
- 换了主题后 GPT 配图也要换色（见「配图」节）。
- **加一档 THEME 是代码改动，按本节直接做、不用先问；改本文件里的行为规则（口径、字号、版式判据）才要先问用户。** 两件事不要混——用户要求“改 skill 前先问”指的是规则，不是色号；停在这里问一句会把整份稿子卡住。
- **加一档 THEME 的固定三步**：① 在 `THEMES` 末尾追加一档，键名一个都不能少（`name / navy / layer×5 / light / pale / arrow / rule / line / ink / red / grey / head`）；② **`THEME` 与 `C = THEMES.get(...)` 这两行必须留在文件末尾**——用 patch 加条目时 `old_string` 只取到 `}` 为止，把这两行一起替换掉会让 `import theme` 直接 NameError，而报错要到几分钟后的 `dense_deck` 才冒出来；③ 加完立刻验证 `PPT_THEME=<名称> python -c "import sys; sys.path.insert(0,'scripts'); import theme; print(theme.THEME, theme.C['name'], theme.C['navy'])"`，再跑全链。暖橙 `warm` 档就是按这套加的：主色 `B24A1E`（白字可读）、章节带 `8C3112`、浅底 `FBEDE1`、强调 `B3261E`。

本技能目前只发布**科研风 · 信息图**一种风格，`meta.style` 的取值只有 `info`。用户计划后续加别的风格（商务极简、深色技术等），所以加风格时按下面的约定做，别在现有风格里塞开关：

- **一个风格 = 一个独立模块**，照 `scripts/info_style.py` 的接口写（页面骨架、组件、版式各自成套），配色 / 字号 / 版式规则互不共用；**内容 JSON 与生成流程不变**，换风格只换实现，让 `meta.style` 指向它。
- **SKILL.md 顶部要写清“有哪几种风格、`meta.style` 怎么选”**，并在 `assets/` 下给每种风格至少一份完整 JSON 示例——用户认稿看的是样例，不是说明。
- **新增风格后同步 README 的「风格库」状态表**（已发布 / 规划中）：README 是别人决定用不用这个技能的第一入口；官方口头承诺过的风格不能只在对话里说，要落到表里。
